# Mutation Log

## Modified
- **ui/index.html** — Added a "Focus" input-group to the Visualize screen's filter row: a text input (`#viz-focus-id`) for a hyperedge/hypernode identifier, a degree select (`#viz-focus-degree`, options 1°/2°/3°), a Focus button (`#btn-viz-focus`), and a Clear button (`#btn-viz-focus-clear`).
- **ui/js/app.js** — Added `vizOneHopNeighbors(id, nodeIds, edgeIds, nodeToEdges, edgeToMembers)` (expands one semantic hop: a hypernode pulls in its hyperedges plus their other co-members; a hyperedge pulls in just its direct members) and `vizComputeNeighborhood(rawNodes, edges, focusId, degree)` (BFS over that one-hop function for `degree` iterations, returns `{nodeIds, edgeIds}` or `null` if the focus id isn't present in that graph's data). `renderViz()` now reads `#viz-focus-id`/`#viz-focus-degree`, filters each selected graph's `rawNodes`/`edges` down to the computed neighborhood before the existing node/link-building logic runs, resolves which viz-node-id (hnode or henode) corresponds to the focus element, pins that node at the scene origin (`x=y=z=0; fx=fy=fz=0`) after nodes/links are built and before `.graphData()` is called, toasts a warning if the focus id isn't found in any selected graph, and shows a focus-aware empty-state message. Added `click`/`keydown`(Enter)/`change` listeners wiring up the new Focus/Clear controls, all routed through the existing `renderViz()`.
