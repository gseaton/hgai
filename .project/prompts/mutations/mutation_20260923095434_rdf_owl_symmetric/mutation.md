# Mutation Log

## Modified
- **hgai/core/rdf_import.py** — During the same graph scan that already builds the `entities` list, now also collects `symmetric_properties: Set[URIRef]` — every predicate declared `<P> a owl:SymmetricProperty` anywhere in the file. When emitting a resource-valued triple's hyperedge, its `flavor` is now `"symmetric"` instead of `"hub"` whenever the predicate is in that set (relation and member order/seq are unchanged — still the predicate's own full expanded IRI, members `[subject (seq 0), object (seq 1)]`). Generalized `edge_tuples`'s shape from `(relation, member_ids, sort_key)` to `(relation, flavor, member_ids, sort_key)`, since flavor was previously hardcoded `"hub"` for every edge the final builder produced and now varies per edge. Updated the module's docstring with the new rule, explicitly contrasting it with `owl:transitive`/`owl:inverse-of` (no separate axiom edge is added — the data edge's own flavor changes instead, since a `symmetric` hyperedge already reads both directions unconditionally via `atomic_pairs`, with no `infer: true` needed).

## Created
- 8 new tests appended to **tests/test_rdf_import.py**: the request's own example reproduced exactly; the relation stays the property's own IRI (not replaced by an axiom string, unlike `owl:inverse-of`); no separate `owl:symmetric` axiom edge is produced; detection is independent of the source file's local OWL prefix; every triple using the same symmetric property gets the flavor, not just the first; a non-symmetric property's data edge stays `hub`; the property's own node still gets ordinary `rdf:type` handling; and all three OWL rules (symmetric, transitive, inverse-of) coexisting on different properties in one file.
