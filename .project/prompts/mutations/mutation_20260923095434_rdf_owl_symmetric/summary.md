# Mutation Summary

## Intent
Third and final piece of RDF/OWL-to-HypergraphAI axiom mapping this session: an ontology's `owl:SymmetricProperty` declaration should make its RDF-imported data facts directly bidirectional in HypergraphAI, the same way the platform already models symmetric relations natively (`flavor: symmetric`, e.g. `scripts/seeds/hgai-hypergraph-eden.export.yml`'s `edge:abel-cain-seth-siblings`).

## Context
The previous two turns this session added `owl:TransitiveProperty` and `owl:inverseOf` support, both of which work by synthesizing a *separate axiom hyperedge* (`owl:transitive`/`owl:inverse-of`) that `hgai/core/inference.py`'s `infer: true` reads at query time to derive missing facts on demand — the original data edges are untouched. `owl:SymmetricProperty` is different in kind: HypergraphAI already has a *structural*, infer-free way to express "every member is mutually equivalent" — the `symmetric` edge flavor itself, whose `atomic_pairs` decomposition (`hgai/core/inference.py`) returns both directions of every pair unconditionally, with no axiom or `infer: true` involved at all. The request's own example asked for exactly this: the data edge's *flavor* changes, not a new axiom edge alongside it — a more direct translation of OWL symmetric-property semantics than routing it through the axiom+`infer:true` mechanism used for the other two.

## What Changed and Why
Detecting which properties are symmetric requires a graph-wide view before any data edge is emitted, since `<P> a owl:SymmetricProperty` and a data triple `<S> <P> <O>` are two unrelated triples (different subjects) that only the predicate `<P>` connects — unlike the transitive/inverse-of rules, which act entirely within one property's own triples. This was folded into the existing single graph-wide scan that already builds the `entities` list (rather than adding a second full-graph pass), so the per-entity loop that emits edges can do a plain set-membership check per predicate. The `edge_tuples` internal tuple shape gained an explicit `flavor` field (previously implicitly `"hub"` for everything) so this, the transitive axiom edge, and every ordinary resource edge share one build/sort path with no special-casing at the point edges are finally assembled.

## Key Decisions
- **No separate `owl:symmetric` axiom edge, by design — matching the request exactly, not extending it.** The `expand_edge`/`get_axiom_edges` machinery in `hgai/core/inference.py` *does* also recognize an `owl:symmetric` axiom (for relations stored as `hub` edges that still need the mirror direction derived on read) — but the request specifically asked for the data edge itself to become `symmetric`-flavored, which is the more direct, `infer`-free translation and was implemented as asked rather than adding the axiom-based alternative unprompted.
- **Verification, in order:** (1) exact reproduction of the request's own example, byte-for-byte; (2) 8 new tests plus the full 81-test RDF suite, mutation-tested (reverting the flavor branch) to confirm 4 tests catch a regression, restored via a `diff`-checked backup copy — not `git checkout`, deliberately avoiding the mistake made two turns earlier in this same session; (3) live, functional verification on a disposable server instance: confirmed the stored edge's flavor via REST, then confirmed via a real SHQL query that a `symmetric`-flavored RDF-imported edge is genuinely queryable bidirectionally with `infer: false` — querying "who is `abel`'s sibling" (the reverse of the asserted `cain → abel` direction) correctly returns `cain`, with no seq-order constraint (a first query attempt using a rigid seq-0/seq-1 hub-style pattern correctly found nothing, which is expected SHQL pattern behavior for a symmetric edge, not a bug — retried with a position-agnostic member pattern, which is the correct way to query a symmetric edge and returned the expected result). Test data and the disposable instance were cleaned up afterward. Full project suite: 535 passed (2 pre-existing, unrelated mesh-ping failures excluded, as in every run this session).
