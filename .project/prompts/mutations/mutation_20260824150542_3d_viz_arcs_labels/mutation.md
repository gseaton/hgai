# Mutation Log

## Modified
- **ui/index.html** — Restored the "Labels" on/off switch (`#viz-show-labels`, checked by default) next to "Auto-rotate" in the Visualize screen's controls row. Added `#viz-label-layer`, an absolutely-positioned overlay `<div>` inside `#viz-cy-wrapper` (sibling of `#viz-canvas`) that holds the projected node/link label elements.
- **ui/css/hgai.css** — Added `#viz-label-layer` (full-bleed absolute overlay, `pointer-events: none`) and `.viz-label` / `.viz-label-node` / `.viz-label-link` rules: small, drop-shadowed text positioned via inline `left`/`top`, node labels bold/white, link labels italic/muted grey.
- **ui/js/app.js** —
  - `renderViz()`: the "hyperedge" virtual link (hyperedge-node → members-node) is now typed and colored by the hyperedge's **flavor** (`label: `flavor:${flavor}``, `color: flavorColor`) instead of a generic constant `"hyperedge"` label/grey color, per the revised `docs/architecture/hypergraph-3d-viz.md` (which now lists this edge as `flavor:hub` in its "3D Graph Elements" section rather than a bare virtual `"hyperedge"` edge). Removed the now-unused `VIZ_HYPEREDGE_LINK_COLOR` constant.
  - Added `vizAssignCurvature(links)`, called just before `graphData()` is set: groups links by source node id and assigns each a distinct `curvature` value spread symmetrically around 0, so multiple relation-links fanning out of the same "members" node (or any shared source) render as visually separate arcs rather than overlapping straight lines.
  - `initViz3D()`: added `.linkCurvature(l => l.curvature || 0)`; simplified `.linkLabel()` to just echo the link's own (now-always-correct) `label` field.
  - Added a self-contained DOM-overlay label system, since restoring literal on/off-toggleable text labels isn't natively supported by `3d-force-graph`'s built-in `nodeLabel`/`linkLabel` (those are hover-only tooltips): `vizProjectPoint(camera, x, y, z)` (projects a 3D world point to normalized canvas space using the live camera's `matrixWorldInverse`/`projectionMatrix` `.elements` arrays directly — no THREE.js reference needed on our side), `vizClearLabelLayer()`/`vizBuildLabelLayer(nodes, links)` (creates one `<div>` per node and per labeled link, rebuilt on every `renderViz()`), and `vizLabelTick()` (a perpetual `requestAnimationFrame` loop, self-guarding on `vizLabelsEnabled` and the Visualize screen's visibility, that repositions every label div each frame by projecting its node's or link's current/midpoint world position). Added the `viz-show-labels` change listener (toggles `vizLabelsEnabled` and hides/shows existing label elements) and started the `vizLabelTick()` loop once at module load.
