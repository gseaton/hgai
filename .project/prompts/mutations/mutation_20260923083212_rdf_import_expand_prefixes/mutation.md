# Mutation Log

## Modified
- **hgai/core/rdf_import.py** — Hypernode/hyperedge **identifiers** (node ids, the `relation` field, and every value in `attributes.rdf_type`) now use the RDF term's full, expanded IRI instead of a compact `prefix:local` CURIE. `_IdMinter.id_for()` returns `str(term)` verbatim for a `URIRef` (only a `BNode` still gets the sanitized `bnode:<label>` scheme, since it has no IRI to expand); `_qname()` is now used *only* for literal-attribute keys (the one deliberate exception — expanding those would break MongoDB's `attributes.<key>` dot-path filter, which SHQL's `attributes: {key: value}` pattern relies on); `_local_name()` is unchanged, still used only for the short, display-friendly `type` field and the label fallback. Removed the now-redundant `attributes.rdf_uri` (the node id itself is already the full IRI). Updated the module's docstring to explain the new behavior and the attribute-key exception in detail.
- **tests/test_rdf_import.py** — Rewrote every test that asserted a CURIE-shaped id/relation to expect the full IRI instead; added dedicated tests reproducing both of the request's own examples (`ex:adam` -> `http://example.com/adam`, `meh:eve` -> `http://meh.io#eve`) and a test asserting attribute keys deliberately stay CURIE-compacted. 65 tests total (was 58).
- **docs/help/notes/web-ui/export-import.md**, **docs/api-reference.md** — Updated the RDF mapping tables to describe full-IRI expansion for ids/relation/`rdf_type`, and the attribute-key exception with its reason.
