# Mutation Summary

## Intent
Follow-up refinement to the RDF-import feature added earlier this session: instead of compacting a subject/object/predicate's namespace prefix into a short `prefix:local` CURIE for hypernode ids and hyperedge relations, expand it to the full absolute IRI — exactly as illustrated by the two examples the user gave (a `/`-delimited namespace and a `#`-delimited one).

## Context
The original implementation deliberately avoided raw IRIs as identifiers, reasoning that an IRI routinely contains '.' (most namespaces are URL-shaped) which could collide with the '.'-prefixed cross-graph member-reference convention and — more importantly — MongoDB rejects (or at best mishandles) a literal '.' inside a document field name. Before making this change, that reasoning was re-verified rather than assumed away: the cross-graph collision risk turned out to be UI-only (`vizParseMemberRef` in Visualize) and already guarded (it only treats a dotted id as cross-graph if the substring before the first '.' matches an *actual, currently-loaded* hypergraph id — never realistic for an IRI). The MongoDB risk, however, is real and specific to *document keys*, not string *values* — and `hgai_module_storage_mongodb/stores/hypernodes.py` (and the hyperedges equivalent) build a literal `f"attributes.{k}"` MongoDB dot-path filter for SHQL's documented `attributes: {key: value}` pattern feature, which *would* break for a dotted key.

## What Changed and Why
Node/hyperedge ids and the `relation` field are plain string *values*, not document keys, so expanding them to full IRIs is safe — confirmed live (see Problem Solving below) rather than assumed. Attribute predicate *names*, however, become MongoDB *keys*, so they alone were kept as sanitized CURIEs; this is documented as a single, explicit, well-reasoned exception in the module docstring, the help topic, and the API reference, rather than silently applying the rule inconsistently. `attributes.rdf_uri` — previously needed to preserve the original IRI now that ids were compact CURIEs — became pure duplication once the id itself carries the full IRI, so it was removed rather than left as dead redundancy.

## Key Decisions
- **Re-derived the safety argument instead of trusting the earlier session's stated rationale.** The original code comments asserted dots-in-ids were unsafe without distinguishing "value" from "key" contexts; grepping the actual storage layer (`f"attributes.{k}"`) found the real, narrow risk, which let this change go further (full IRIs everywhere sensible) while still being conservative exactly where it matters (attribute keys).
- **Verified, not assumed, that the change is safe in practice**: re-ran the full RDF test suite (65 tests, all rewritten to expect full IRIs) plus a mutation test (reverting the relation to a CURIE) to confirm the suite would actually catch a regression. Live end-to-end against a disposable second server instance: imported RDF with both the `/`- and `#`-namespace examples verbatim from the request, confirmed the stored ids/relations match exactly; ran an SHQL query filtering by the still-CURIE-compacted `attributes: {foaf:name: Adam}` (confirms the one exception still works); ran an SHQL edge/member join keyed on the new full-IRI ids (confirms they resolve correctly in queries, not just storage); rendered the imported graph in Visualize and inspected the live scene data, confirming no node was misclassified as a cross-graph reference despite its id containing dots. No console errors. Full project suite: 505 passed (2 pre-existing, unrelated mesh-ping failures excluded, consistent with every prior run this session).
- **Test data cleanup**: deleted the one hypergraph created for this round of testing (`expand-test`) from the disposable instance and stopped it; left two unrelated hypergraphs (`eden-ttl`, `eden-ttl-project-1`) and a staged `scripts/seeds/adam-eve.ttl` file visible in `git status` untouched, since neither was created by this work.
