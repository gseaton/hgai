# Mutation Summary

## Intent
Fix the diagnosed gap from the prior turn: `edge:brother-sibling` (relation `skos:broaderTransitive`, members `[family:brother, family:sibling]`) generated no inferred hyperedges because the reasoning engine only ever recognized the literal string `"skos:narrowerTransitive"` as a superproperty-projection axiom — `skos:broaderTransitive` was documented everywhere as the conceptual mirror image but never actually checked in code. The user asked for two things together: native recognition of both spellings, and support for an explicit `owl:inverse-of` relationship declared between them.

## Context
`expand_edge`'s superproperty-projection rule (Phase 3 of the three synthesis rules it applies) previously did exactly one `walk_closure(relation, "skos:narrowerTransitive", direction="backward")` call. `skos:narrowerTransitive [broader, narrower]` (hub decomposition: hub=broader, spoke=narrower) requires walking *backward* from a narrow fact-relation to find its broader ancestors — that's the only axiom shape the engine understood. This session had already established (in the diagnosis conversation immediately preceding this one) that `skos:broaderTransitive [narrower, broader]` is the exact mirror-image encoding of the same fact (hub=narrower, spoke=broader), which would need to be walked *forward* instead — and that the existing generic `owl:inverse-of` fact-expansion rule (already used for domain relation pairs like `rel:parent`/`rel:child`) is architecturally the right tool for declaring that two relations are inverses of each other, rather than adding more hardcoded relation-string special cases.

## What Changed and Why
Extracted the superproperty-projection lookup into a new `_broader_chain()` helper that unions three walks instead of one:
1. `skos:narrowerTransitive`, backward (unchanged, pre-existing behavior).
2. `skos:broaderTransitive`, forward (new — hardcoded/native, matching the request's first half: this alone fixes the reported edge with zero additional axioms).
3. Any relation R for which an `owl:inverse-of[skos:narrowerTransitive, R]` (or `[R, skos:narrowerTransitive]` — `_other_member` doesn't care about order) hyperedge exists, walked forward like `skos:broaderTransitive` — the request's second half: `skos:broaderTransitive` becomes the *expected default* spelling of the mirror image without being the *only* one a graph is allowed to assert, using the same `owl:inverse-of` declaration pattern already established for domain relations rather than a second bespoke mechanism.

Results are deduped by which broader relation was reached (first hop found wins, matching `walk_closure`'s existing single-path-per-node contract), so a redundant `owl:inverse-of[skos:narrowerTransitive, skos:broaderTransitive]` declaration alongside the two native literal forms doesn't produce duplicate inferred edges — confirmed in live verification below.

## Key Decisions
- **`skos:broaderTransitive` is hardcoded natively, not left to require an `owl:inverse-of` declaration** — the user explicitly asked for both "natively" (unconditional) and the inverse-of mechanism (extensible), as two distinct asks, not one satisfying the other. Native support means the exact reported edge works immediately with no additional axiom needed.
- **The generic `owl:inverse-of` extension is anchored specifically on `skos:narrowerTransitive`** (looking up axioms naming it, then walking whatever it's declared inverse to) rather than trying to make the mechanism fully symmetric/bidirectional in the code itself — `owl:inverse-of` edges are already direction-agnostic at the data level (`_other_member` finds "the other one" regardless of which member is listed first), so anchoring the *lookup* on one canonical vocabulary term is sufficient to cover both authoring orders without added complexity.
- **Dedup by reached-relation id, not by which source found it** — a relation reachable via more than one route (e.g. both the native `skos:broaderTransitive` literal and an explicit redundant `owl:inverse-of` declaration naming it) is harmless, not double-counted, verified directly rather than assumed.
- Considered but rejected: trying to make the *closure* (`expand_edge_closure`'s fixed-point loop) automatically derive one axiom spelling from the other via the existing generic inverse-of *fact*-expansion rule applied to axiom edges themselves (since axiom edges are ordinary hyperedges that technically could flow through `expand_edge` as "facts" when no relation filter is applied). This does not actually work end-to-end: `get_axiom_edges`/`walk_closure` only ever query persisted storage, never the closure's in-memory frontier of newly-synthesized-but-not-yet-written candidates, and `expand_edge_closure`'s frontier is replaced (not accumulated) each iteration — so a same-call derivation of "narrowerTransitive from broaderTransitive" would need a persisted round-trip via Project Inference before it could actually take effect, making it unreliable as the *primary* mechanism. Native recognition avoids that fragility entirely by resolving both spellings via fresh, independent DB queries every time `_broader_chain` runs.

## Live Verification Performed
Started an isolated test server (`HGAI_MONGO_DB=hgai_broader_fix HGAI_PORT=8399`) and reproduced the exact reported scenario in a fresh graph `brotherfix`: axiom edge `skos:broaderTransitive [family:brother, family:sibling]` plus a fact edge `family:brother(john, mike)`. Calling `POST /graphs/brotherfix/infer/expand` on the fact edge now correctly returns one inferred edge: `family:sibling(john, mike)`, tagged with the correct `_source_edge`/`_axiom` provenance — confirming the reported bug is fixed.

Additionally verified:
- **Generic extensibility**: declared `owl:inverse-of[skos:narrowerTransitive, custom:superOf]` (an arbitrary, non-canonical relation name) plus an axiom edge `custom:superOf [rel:colleague, rel:coworker]` and a fact `rel:colleague(amy, bob)` — `/infer/expand` correctly derived `rel:coworker(amy, bob)`, proving the mechanism isn't limited to the two blessed spellings.
- **No duplication**: added a redundant explicit `owl:inverse-of[skos:narrowerTransitive, skos:broaderTransitive]` declaration on top of the already-working native broaderTransitive case — re-running expand still returned exactly one `family:sibling` result, not two.
- **Regression-free**: the original `skos:narrowerTransitive` convention (`rel:parent`/`rel:father`, from earlier sessions) still correctly derives `rel:parent(adam, cain)` from a `rel:father` fact, unchanged.
