# Mutation Summary

## Intent
Immediately after adding an optional Phase 13 (3D interactive hypergraph visualization) to `build-plan.md`'s §14, the assistant had flagged that the companion prompts file (`hgai-v0.2-plan-prompts.md`, which contains one ready-to-submit Claude Code prompt per phase) still only covered Prompts 0–12 and hadn't been updated to match. The user asked for a Prompt 13 to be added there too, explicitly as optional — consistent with how Phase 13 itself was scoped in `build-plan.md`.

## Context
- `hgai-v0.2-plan-prompts.md` exists specifically so a human operator can submit one self-contained prompt per phase to a fresh Claude Code (or similar) session, in order, with the repo's own state (not chat history) carrying continuity between phases. Every existing prompt (0–12) follows the same shape: tells the agent to read `build-plan.md` first (with pointers to the specific relevant sections), states which prior phases are assumed complete, restates that phase's concrete deliverables and exit criteria inline, and calls out the specific defect/design constraint from `build-plan.md` most relevant to that phase.
- The new Prompt 13 needed to follow that same shape while also carrying forward Phase 13's two defining properties from `build-plan.md`: that it's optional (not part of the required 0–12 sequence), and that it's purely additive to `apps/web-ui` with zero backend/API changes — reusing HQL member-filtering (§6.1) and REST edge hydration (§7) rather than introducing new backend surface.
- Prompt 11 (CLI shell & Web UI) was the closest existing precedent for a UI/UX-verification-style prompt (ending in an instruction to actually run the stack and report what was observed, not just that the build compiled) and was used as the template for Prompt 13's closing verification instruction.

## What Changed and Why
Appended a new "## Prompt 13 — 3D interactive hypergraph visualization *(optional)*" section after Prompt 12, following the file's established format exactly: a single fenced instruction block containing the read-first directive, an explicit optionality gate ("only proceed if you were explicitly asked to build this phase"), the full deliverable list translated from `build-plan.md`'s Phase 13 entry into second-person implementation instructions, an explicit reminder not to build a new backend endpoint for the double-click-focus feature (since that requirement — reuse existing HQL/REST capability — was easy to accidentally violate if an agent didn't have `build-plan.md` fully in view), and the same "actually run it and report what you saw" closing instruction used in Prompt 11.

## Key Decisions
- Placed Prompt 13 at the end of the sequence (after Prompt 12) rather than out-of-band or in a separate "optional prompts" section, since the file's existing structure is a strict ordered list and Phase 13 is likewise the last, optional phase in `build-plan.md`'s own ordering — no structural change to the file was needed to accommodate an optional final entry.
- Repeated the "reuses existing HQL/REST capability, do not build a new backend endpoint" instruction explicitly in the prompt body (not just implied by omission) — because this prompt, unlike most of the others, describes a feature (double-click focus) whose most natural naive implementation would be a new dedicated backend query, and the prompt needed to actively steer an implementing agent away from that even without full context from the earlier design conversation that established the reuse decision.
