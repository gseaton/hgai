# Mutation Summary

## Intent
The user wanted a self-contained demo package for HypergraphAI: a markdown slide deck plus the accompanying data/query files, suitable for two audiences at once — someone training new engineers live, and a technical engineer running the demo entirely unassisted from the deck alone. The deck needed to start from a clean install with no pre-existing demo artifacts, cover HypergraphAI's major features and advantages, include real `.hql`/`.shql` query files, and explain both the demo steps and the underlying knowledge-graph/hypergraph concepts for readers new to the domain.

## Context
HypergraphAI (this repo) is a hybrid semantic hypergraph/document platform with two query languages (HQL — Mongo-style filter/aggregate; SHQL — SPARQL-style pattern matching), a REST API, a Web UI, an interactive shell (`hgsh.sh`), and an MCP server for AI-agent access. The repo already ships one seed dataset (`scripts/seed_data.py`, a "Three Stooges" hypergraph called `hello-world`) but the user's request implied a fresh, standalone dataset rather than reusing that one, and the target folder name (`demo-alpha`) suggested a distinct demo identity. There was no existing `docs/decks/` content to follow as precedent, so the deck's structure (agenda → concepts → numbered phases → wrap-up) was designed from scratch, informed by the README's own documented feature set (hypernodes/hyperedges/flavors, temporal PIT queries, HQL/SHQL syntax, MCP tool payloads, spaces/RBAC, and the inferencing roadmap).

## What Changed and Why
Before writing anything, the README, the HQL/SHQL engine source (`hgai_module_hql/engine.py`, `hgai_module_shql/engine.py`, `hgai_module_shql/parser.py`), the Pydantic-free... (note: this project itself forbids Pydantic-model-as-DTO patterns per its own `no_classes_rule.md`, but that rule applies to *this repo's own code*, not to the deck's Markdown/YAML content) data models (`hgai/models/hypernode.py`, `hyperedge.py`, `hypergraph.py`), the shell (`shell/hgai_shell.py`), and the storage layer's Mongo query-building (`hgai_module_storage_mongodb/stores/*.py`) were all read to ground every claim and command in actual behavior rather than the README's prose alone (which the investigation revealed is occasionally imprecise — see Key Decisions).

A fictional "Acme Robotics" engineering-org dataset was designed (3 teams, 7 people, 5 skills, 2 projects, 6 semantic RelationType nodes, 23 hyperedges) specifically to exercise every major feature in one coherent story: n-ary hub edges (one person → many skills, one project → many staff), directed/symmetric edge flavors, temporal team-roster versioning (an engineer moving teams, to drive point-in-time queries), and deliberately uneven mentorship coverage (to drive an OPTIONAL-join example).

Rather than write the 14 query files from documentation alone, a disposable local HypergraphAI server was started (`.venv/bin/python -m hgai.main --port 8399 --mongo-db hgai_demo_validate`, using the machine's already-running local `mongod`) and every single file — the import dataset and all 7 `.hql` + 7 `.shql` query files — was executed against it via the real REST API, the real MCP `/mcp/` endpoint, and the real `hgsh.sh` shell (`import -f`, `query -f`, `shql -f`) before being written into the deck. The disposable server and its MongoDB database were torn down afterward; the user's own separately-running `hgai-alpha` dev server (port 8361) was deliberately left untouched throughout.

## Key Decisions
- **New dataset instead of reusing `hello-world`.** The Three Stooges seed data is small (2 Person types effectively, few relations) and wouldn't showcase n-ary hub edges, multiple edge flavors, or a temporal-move story as clearly as a small org chart does. A fresh, from-scratch dataset also matches "clean install, no demo artifacts" more literally than instructing the reader to run the existing `scripts/seed_data.py`.
- **Empirical verification over documentation-only writing.** While building the SHQL examples, live testing surfaced two real engine behaviors not obvious from the README: (1) YAML flow-style mappings like `{ bind: ?var }` fail to parse because bare `?` is a reserved YAML indicator in flow context — the fix is quoting (`{ bind: "?var" }`), which the README's own examples don't do; (2) when a hyperedge pattern has two or more *unbound* "wildcard" member sub-patterns, the engine's `type:` constraint on those sub-patterns is not actually enforced during member-matching, and multiple same-type members (e.g. several skills on one hub edge) will not all expand correctly — the reliable fix is binding each variable via a preceding top-level `node:` pattern and then re-anchoring it in the edge's members list via matching `bind`+`id`. Both findings are called out explicitly and accurately in the deck (Phase 6's "practical tip" callout) rather than being silently worked around, since the deck's stated audience includes engineers running it completely unassisted — a query that silently returns wrong-but-plausible results would be worse than an example that simply failed to parse.
- **Honest live-vs-roadmap section for inferencing (Phase 10).** Source inspection of `hgai/core/inference.py` showed `infer_inverse_edges()` and `check_transitive_relation()` are fully implemented but are not called from any HQL/SHQL/REST/MCP code path in the current codebase — i.e., the README's "Inferencing" section documents engine-level capability that isn't yet queryable. Rather than demo a feature that would silently fail to do anything when an engineer tries it live, the deck names this gap directly and reframes it as a legitimate "the data model is ready, the query surface isn't yet" story.
- **`$or` example moved from hypernodes to hyperedges.** An initial `$or` example filtering Person nodes by `attributes.level` returned zero results when tested live; tracing the HQL engine (`_build_node_search_filters` in `hgai_module_hql/engine.py`) showed unrecognized top-level `where` keys are only passed through to MongoDB for hyperedge searches (via `extra_filters`), not hypernode searches (where they're incorrectly folded into the `attributes` dict). The deck's q05 example was redesigned around hyperedges (`$or` across `relation` values) instead, and a short accurate note was added rather than presenting a broken example as canonical.
