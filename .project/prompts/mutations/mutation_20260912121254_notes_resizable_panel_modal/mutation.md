# Mutation Log

## Modified
- **ui/index.html** — Added `#notes-sidebar-resize-handle` (a draggable strip, `role="separator"`, keyboard-focusable) between `.notes-folder-sidebar` and `.notes-main` in the Notes screen.
- **ui/css/hgai.css** — `.notes-folder-sidebar`'s width now comes from a `--notes-sidebar-width` CSS variable (default 260px) instead of a fixed `flex: 0 0 260px`; added `.notes-sidebar-resize-handle` styling (thin draggable strip, `cursor: col-resize`, hover/dragging highlight) and a `body.notes-sidebar-resizing` cursor-lock class. Added a resizable-modal block for `#modal-note`: loosened `.modal-dialog`'s max-width well past Bootstrap's `.modal-xl` default, put `resize: both` on `.modal-content` (the same native-corner-grip affordance this app's JSON-attributes textareas already use elsewhere), and gave `.modal-body` its own `overflow-y: auto` so shrinking the window scrolls the content instead of clipping it while the header/mode-bar/footer stay fixed.
- **ui/js/app.js** — Added `notesApplySidebarWidth`/`notesRestoreSidebarWidth`/`notesInitSidebarResize` (pointer-drag + arrow-key resize of the folder sidebar, width persisted to `localStorage` under `hgai_notes_sidebar_width`), called once at script load. Added `restoreNoteModalSize`/`initNoteModalResizePersistence` (a debounced `ResizeObserver` on `#modal-note .modal-content` that persists its size to `localStorage` under `hgai_note_modal_size` whenever the user drags the native resize grip while the modal is open) and a call to `restoreNoteModalSize()` at the top of `openNoteModal` so a previously-chosen size is reapplied on every open.
