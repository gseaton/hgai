# Mutation Summary

## Intent
RDF-imported (and, in principle, any) hypernode/hyperedge attribute keys are deliberately kept as compact `prefix:local` CURIEs by [[rdf-owl-symmetric-axiom-edge]] and the digit/quote literal-value work earlier in this project's history — a documented, load-bearing design decision, since expanding them to full IRIs would break SHQL's `attributes: {key: value}` MongoDB dot-path pattern filter. That's correct for querying, but it means every RDF-imported attribute carries a visible prefix (`ex:sex`, `foaf:age`) that a user browsing the Web UI may just want stripped for readability, without touching the underlying SHQL-safety constraint. The user asked for an opt-in toggle in the Import Hypergraph window to do exactly that: rewrite `ex:sex` → `sex` and `http://example.org/description` → `description` on request.

## Context
The Import Hypergraph modal (`ui/index.html`, wired in `ui/js/app.js`) is the single UI entry point for both native export-file imports and RDF imports — both call through `ui/js/api.js`'s `importGraphFile`/`importRdfFile`, which hit `POST /graphs/import` and `POST /graphs/import/rdf` (and their space-scoped equivalents) respectively. Both of those REST endpoints funnel through a shared `run_import()` helper in `hgai/api/transfer_http.py`, which is the one choke point every import path (native and RDF, unowned and space-scoped) passes through before handing the parsed document to `hgai/core/transfer.py`'s `import_document()`. That made `run_import()` the natural place to apply an optional attribute-key rewrite to the in-memory document's `nodes`/`edges` lists, rather than duplicating the logic in `rdf_import.py` (RDF-specific) and `transfer.py` (native-file-specific) separately — and it means the toggle also works for a native `.export.yml` file whose attribute keys happen to be CURIE- or IRI-shaped (e.g. one re-exported from a previously RDF-imported graph).

## What Changed and Why
Added a local-name extraction function (`_local_attribute_name`) that mirrors the "local name" concept `hgai/core/rdf_import.py` already uses for `rdf:type`/label display values — after the last `#` or `/` (whichever comes later in the string), falling back to the last `:` only when neither is present (so a full IRI's own `http:` scheme colon is never mistaken for the split point). This function drives `_strip_attribute_key_prefixes`, which rewrites a single `attributes` dict's keys — but only when doing so is unambiguous: if two different original keys would strip to the same local name (e.g. `foaf:name` and `dc:name` both → `name`), or a stripped key would collide with an already-unprefixed key already in the document, every key in that collision group is left exactly as it was, since silently merging two different attributes into one would destroy data, which is a strictly worse outcome than leaving a prefix visible. `strip_attribute_prefixes_in_doc` applies this to both `nodes[*].attributes` and `edges[*].attributes` (both models carry an `attributes` field, so the rewrite isn't RDF-specific even though RDF import is what makes CURIE keys common).

The option surfaces as `strip_attribute_prefixes` (a boolean query parameter, default `false`, so nothing changes unless requested) on all four import endpoints the modal can call, and as a same-named checkbox in the modal itself, positioned below the existing create/merge mode radios.

## Key Decisions
- Applied the rewrite in `hgai/api/transfer_http.py`'s shared `run_import()` rather than inside `rdf_import.py`, so a single implementation covers both native and RDF imports (and both unowned and space-scoped variants) without duplicating the local-name logic across two modules with different natural data shapes (an rdflib graph vs. a parsed export dict).
- Chose "leave both keys untouched on collision" over an alternative like "keep the first, drop the second" or "merge into a list" — a toggle whose entire purpose is convenience should never be the reason two genuinely different attributes (e.g. `foaf:name` vs. `dc:name`, a person's own name vs. a Dublin Core catalog name) silently become indistinguishable or lossy. Verified this behavior directly in the live end-to-end check (see below).
- Scoped the new query parameter to the two import endpoints the Import Hypergraph modal actually calls (`/graphs/import`, `/graphs/import/rdf`, and their space-scoped equivalents) rather than also the separate `/{graph_id}/import` "merge into existing, JSON body" endpoint — that endpoint isn't reachable from this modal, and the request was specifically about the Import window.

## Verification
Live-verified on a disposable server (port 8368, cleaned up afterward): confirmed the new query parameter on both the RDF and native import endpoints, confirmed the collision-avoidance behavior with a real `foaf:name`/`dc:name` clash (both correctly left prefixed while `ex:sex`/`foaf:age` stripped cleanly), and drove the actual Web UI end-to-end in a real browser (Claude in Chrome) — uploaded a `.ttl` file, checked "Suppress Attribute Prefixes," ran the import, and confirmed via REST that the resulting hypernode's attributes matched the direct-API test exactly. 15 new unit tests pass, mutation-tested (temporarily disabled the stripping logic; 4 targeted tests correctly failed; restored via `diff`-verified `cp`, not `git checkout`). Full project suite: 556 passed.
