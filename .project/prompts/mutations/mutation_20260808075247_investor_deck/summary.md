# Mutation Summary

## Intent
The user wanted a Markdown slide deck at `notes/decks/hgai-investor.md`, aimed at technically-literate potential investors and/or adopters, pitching HypergraphAI as a context/memory store for AI agentic systems, and explicitly requiring TAM, SAM, and SOM market sizing.

## Context
- A prior investor deck already existed at `docs/investor-pitch-deck.md` (18 slides, no SOM, unsourced TAM/SAM figures). The new file is a distinct, new path — not an edit of that file — so it was treated as a fresh deck rather than a patch, while still drawing on the existing deck's structure and business-model figures where they held up.
- Reviewing that existing deck against the actual codebase (using verified findings from earlier in this session) surfaced a material accuracy problem worth not repeating: it claims "SKOS Inferencing Built In" and lists "inferencing" under shipped traction, but `hgai/core/inference.py` is confirmed dead code (zero call sites anywhere), and SKOS fields are actively stripped from every HQL/SHQL query result. It also understates the MCP tool count (claims 19; the server actually registers 25 `@mcp.tool()` functions).
- The user's framing ("funding and/or adopting... some technical knowledge") signaled the deck needed to survive scrutiny from a reader who can and might clone the repo and check claims directly — not just a standard VC narrative.
- No web-search-sourced market data existed in the repo for TAM/SAM/SOM; the existing deck's $800M SAM / $8B TAM figures were asserted without visible sourcing or methodology, and had no SOM at all despite the user's explicit request for one.

## What Changed and Why
- **Created `notes/decks/hgai-investor.md`** as a new 21-slide deck (not an edit of the existing `docs/investor-pitch-deck.md`, which was left untouched).
- **Corrected the inferencing claim**: the new deck's differentiators, architecture diagram, competitive table, and traction slide all describe inferencing as "architected, not yet wired up" / "🔶 Roadmap" rather than shipped — consistent with what the codebase actually shows, and consistent with `README.md`'s own Roadmap section and this session's earlier inference-engine research. A dedicated "What's Actually Built Today" slide (Slide 4) was added specifically so a technical reader gets an accuracy-first capability table before any market-sizing or business claims.
- **Corrected the MCP tool count** from the old deck's "19 tools" to the verified "25 tools" (counted directly via `grep -c "@mcp.tool()" hgai_module_mcp/server.py`).
- **Added a "Try It Before You Buy It" slide (Slide 8)** aimed specifically at technical adopters — a real `docker compose up` / `hgai-shell` path, since the platform is MIT-licensed and self-hostable, giving a technical evaluator a way to verify claims directly rather than take the deck's word for it.
- **Built TAM/SAM/SOM with real, current, cited sources** (via live web search, run at deck-drafting time — August 2026): global Knowledge Graph market, Graph Database market, and Agentic AI market figures from MarketsandMarkets, Mordor Intelligence, Verified Market Reports, Research and Markets, IDC, and Gartner. TAM is defined narrowly (Knowledge Graph + Graph Database markets only — deliberately excluding the much larger but irrelevant-to-this-product $497B AI infrastructure/compute spending figure, to avoid the common inflated-TAM pitfall a technical investor would catch). SAM applies an explicitly-labeled 12% "knowledge/memory-layer share" assumption to the agentic AI market figure, flagged as an assumption rather than presented as sourced fact. SOM is built bottom-up from realistic GTM capacity (customer count × blended ACV) rather than as a top-down percentage of SAM, and cross-checked against the funding ask's team size — a different, complementary methodology from the top-down TAM/SAM, shown transparently as such.
- **Retained and adapted** the business model, go-to-market, competitive landscape, and funding-ask structure from the existing `docs/investor-pitch-deck.md`, since those held up against the codebase (RBAC, JWT+API key auth, mesh federation, Spaces, MIT license were all independently verified as real, shipping capabilities).
- **Added a Sources section** at the end of the deck listing every cited market-research URL, plus an explicit note distinguishing sourced figures from the deck's own stated assumptions (the SAM share and SOM inputs) — so a reader can tell which numbers to trust as-is versus which to challenge/refine with primary research before a real raise.

## Key Decisions
- **New file, not an edit of the existing deck**: the user specified the exact new path, and the existing deck's unaddressed accuracy problems (inferencing claim, MCP count) meant a from-scratch, verified pass was more appropriate than propagating those issues into a "TAM/SAM/SOM update."
- **Correcting rather than repeating the inferencing overclaim**: given this session had already done deep, code-verified research establishing that inferencing is unimplemented, silently copying the old deck's "built-in" claim into a new document would have been reproducing a known-false statement. Framing it as a roadmap item — and adding an entire slide auditing what's real vs. not — was judged more defensible for a technically literate audience than omitting the discrepancy.
- **Using live web search for market figures instead of reusing the old deck's unsourced numbers**: since the user explicitly required TAM/SAM/SOM and the existing deck's figures had no visible methodology, sourcing current third-party research (with citations included in the deck) was judged necessary for the numbers to survive diligence, rather than presenting another set of unsourced estimates.
- **Explicitly flagging assumption-based figures (SAM share, SOM inputs) as assumptions, not facts**: rather than presenting a single polished number, the deck shows its work — this is intentionally more defensible to a technical/analytical investor than a deck that hides its estimation methodology.
