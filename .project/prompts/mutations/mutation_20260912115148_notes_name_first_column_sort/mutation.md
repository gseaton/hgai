# Mutation Log

## Modified
- **hgai/api/routers/notes.py** — Added `NOTE_SORT_FIELDS` (`label`, `name`, `owner_username`, `status`, `system_created`, `system_updated`) and a `sort` query parameter to `list_notes`, parsed via the existing `parse_sort_param` helper (already used by the hyperedges/media list endpoints) and passed through to `list_notes_visible_to`.
- **hgai/core/notes.py** — `list_notes_visible_to` gained a `sort: Optional[List[Tuple[str, int]]]` parameter, passed to `NoteFilters(sort=sort)` — the storage layer already supported a `sort` filter (built when the Notes feature was first added, but never wired to a caller until now).
- **ui/index.html** — Reordered the notes table header so `Name` is the first column (before `Label`); made `Name`, `Label`, `Owner`, `Updated`, and `Status` into `sortable-th` columns (matching the exact class/data-attribute pattern the Media/Hypernode/Hyperedge tables already use) — `Tags` and `Shared With` stay non-sortable since they're arrays, not scalar fields.
- **ui/js/app.js** — Added `notesSort: []` to `State`. `loadNotes()`'s row template reordered to put Name first (now carrying the icon + click-to-open affordance, matching every other table's "first column is the clickable identity column" convention) with Label following as a plain sortable text cell; added `sort: sortParam(State.notesSort)` to the list request and an `updateSortIndicators('notes')` call — both reusing the fully generic multi-column sort infrastructure (`sortParam`, `updateSortIndicators`, `handleSortableThClick`, and the single delegated `.sortable-th` click-listener loop) already shared by every other sortable table in this app, so no new sorting logic was needed.
