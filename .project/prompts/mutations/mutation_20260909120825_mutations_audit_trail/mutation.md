# Mutation Log

## Modified
- **hgai/models/common.py** — Added `MutationDelta` (`field`, `old`, `new`) and `MutationRecord` (`ts`, `by`, `mutation`: str kind, `delta`: `List[MutationDelta]`) Pydantic models, shared by hypernodes and hyperedges.
- **hgai/models/hypernode.py** — Added `mutations: List[MutationRecord]` to `HypernodeInDB` (server-managed; not on `HypernodeCreate`/`HypernodeUpdate`, so it can't be set via the API request body — only read back in responses).
- **hgai/models/hyperedge.py** — Same addition of `mutations: List[MutationRecord]` to `HyperedgeInDB`.
- **hgai_module_storage/filters.py** — Added `mutations: Optional[List[Any]] = None` to both `HypernodePatch` and `HyperedgePatch` dataclasses.
- **hgai_module_storage_mongodb/stores/hypernodes.py** — Added `"mutations"` to the whitelist of patch attributes `update()` writes into MongoDB's `$set`.
- **hgai_module_storage_mongodb/stores/hyperedges.py** — Same addition to its `update()` whitelist.
- **hgai/core/engine.py** — New "Mutation Tracking" section: `HYPERNODE_TRACKED_FIELDS` / `HYPEREDGE_TRACKED_FIELDS` (which fields participate in delta tracking — excludes system/managed fields like `id`, `hypergraph_id`, `hyperkey`, `system_created`/`system_updated`, `created_by`, `version`, `mutations` itself); `_is_blank()`, `_create_delta()`, `_update_delta()` (compute field-level deltas); `_append_mutation()` (appends a new mutation entry unless it's empty or identical to the most recently recorded entry — the redundant-sequential-mutation rule — returning the original list object unchanged, by identity, when nothing is appended). `create_hypernode()`/`create_hyperedge()` now compute a `"create"` mutation entry from the new document's populated fields and store it in `doc["mutations"]`. `update_hypernode()`/`update_hyperedge()` now compute a `"mutate"` delta against the existing document and, only if something new needs to persist (checked via list identity against the existing mutations list), pass the extended `mutations` list through the patch. `import_hypergraph_data()` now strips any incoming `mutations` field from imported node/edge data before reconstructing `HypernodeCreate`/`HyperedgeCreate` (mirroring the existing `hyperkey` strip), so a re-import gets a fresh, accurate `"create"` entry instead of carrying forward stale history.
- **ui/index.html** — Added an (initially hidden) `<div id="modal-detail-history">` container above the raw-JSON `<pre>` in the shared View/Detail modal.
- **ui/js/app.js** — Added `fmtMutationValue()` (renders a delta's old/new value: em dash for null/undefined, compact JSON for objects/arrays, escaped text otherwise) and `renderMutationHistory()` (renders a `mutations` array as a scrollable, newest-first timeline: colored CREATE/MUTATE badge, formatted timestamp + `by`, and each delta's `field: old → new`; hides the whole section when there are no mutations). Wired into `showDetail()`, which now calls `renderMutationHistory(obj.mutations)` before opening the modal, so the View action on both hypernodes and hyperedges shows the audit trail above the existing raw-JSON dump.
- **tests/test_engine.py** — Added 9 new unit tests covering: create-delta blank-field filtering, update-delta only-actual-changes filtering, empty-delta suppression, first-entry append, redundant-sequential-entry suppression (by identity), non-adjacent repeats still appending, and same-delta-different-kind still appending.
