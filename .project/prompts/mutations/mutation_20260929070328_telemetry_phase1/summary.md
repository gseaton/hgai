# Mutation Summary

## Intent
Implement Phase 1 ("Foundation") of docs/architect/telemetry-20260929061557.md: the telemetry module skeleton, settings, `emit()` API, REST instrumentation, and an admin status endpoint — off by default, no behavior change for existing deployments.

## Context
Followed the plan's file-by-file design closely: mirrored `hgai_module_mesh/scheduler.py`'s background-task shape, `hgai_module_mesh/engine.py`'s shared-HTTP-client pattern, and the Mesh/SHQL/MCP/AgentChat module-mounting convention (`try/except BaseException`, non-fatal) in `hgai/main.py`. Confirmed via a real FastAPI `TestClient` run (not just unit mocks) that the REST middleware's route-template reconstruction, account hashing, and outcome mapping all work end-to-end against the actual app, including a genuine MongoDB-backed request cycle.

## What Changed and Why
`hgai_module_telemetry` is a new optional module: `emit()` pushes an OTEL-shaped event onto a bounded in-memory queue (oldest-drop when full) without ever awaiting; a background task batches by size or a flush interval and dispatches to a `select_exporter`-chosen destination, retrying with capped exponential backoff before dropping a batch. `HTTPExporter` posts the plan's `hgai-envelope` format; `NullExporter` is used both when telemetry is disabled and, in this phase, when it's enabled but no endpoint is configured (local storage, the plan's no-endpoint fallback, is Phase 3a) — the difference is logged once at startup, not per event, and documented in code and `.env.example` as reserved settings. `TelemetryMiddleware` is a pure ASGI middleware (not `BaseHTTPMiddleware`, to avoid its response-buffering behavior) that reconstructs the matched route's path template from `scope["path_params"]` rather than the raw URL, so `feature` is always a template per the plan's privacy rule. It reads the authenticated account from `scope["state"]["account"]`, which required one small, additive change to `hgai.core.auth.get_current_account` (adding a `Request` parameter and one line stashing the account) rather than re-authenticating or duplicating the auth dependency chain.

## Key Decisions
- **Per-deployment salt reused `settings.secret_key`** rather than adding a new persisted-settings mechanism just for a telemetry salt — it already has the security property the plan asked for (stable, per-deployment, non-public), and every deployment already has one.
- **"Enabled but no endpoint" is not silent**: the background task and queue still run so `/telemetry/status` is meaningful, but the destination is `NullExporter` with a clear one-time startup warning pointing at the plan's Phase 3a, rather than either crashing or pretending to succeed.
- **Route-template reconstruction** substitutes `scope["path_params"]` values back into the raw path rather than re-implementing Starlette's route matching a second time; verified against a real running app rather than assumed from reading Starlette's source, since this FastAPI/Starlette version's internal routing representation (`_IncludedRouter`) turned out to differ from what static inspection suggested.
- **`hgai.deployment.mode`** (a resource attribute the plan's §3 schema names but doesn't back with a setting) is inferred from whether the endpoint's host is `hypergra.ai`, documented in code as a placeholder rather than a real config surface, since adding a dedicated setting for one cosmetic attribute felt like scope creep for Phase 1.
- **Not implemented in this phase** (all explicitly out of scope per the plan's phase table): SHQL/MCP/Web-UI/shell instrumentation, `__local-telemetry` local storage, the Help/disclosure docs, and `otlp-http-json`.

## Verification
`python -m pytest tests -q` — 903 passed (2 pre-existing, unrelated mesh-ping failures deselected, same as before this change). New `tests/test_telemetry.py` (30 tests) covers identity hashing, event/envelope shape, exporter behavior against a mocked HTTP client, engine behavior (disabled-means-silent, never-blocks, batching, backoff-then-drop, sampling, status redaction), and REST middleware integration against a real ASGI request cycle.
