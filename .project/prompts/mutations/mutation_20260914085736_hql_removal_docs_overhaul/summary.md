# Mutation Summary

## Intent
The user asked for all project documentation to be updated to reflect the current state of the codebase, explicitly citing "removal of HQL query language" and "improved documentation for SHQL query language, inferencing" as examples. Since HQL was still fully live in the code at that point, executing that literally would have meant writing documentation that claimed something false. A clarifying question resolved this: the user chose to actually execute the HQL code removal first, then bring every piece of documentation into alignment with that new reality — matching the sunset-HQL recommendation from earlier in this session (see `.project/prompts/asks/ask_202609140725_hql_sunset_assessment/` and `.project/prompts/asks/ask_202609140820_hql_sunset_reassessment/`).

## Context
- Two prior turns in this session built the case for this: an assessment recommending SHQL consolidation once `aggregate`/`group_by` was ported onto SHQL and HQL's last unique capability disappeared, then a reassessment (after learning the project is pre-release with no legacy user base) upgrading that to an explicit recommendation to sunset HQL.
- That earlier work had already split the eventual sunset into two tracks: "core removal" (engine/API/UI/CLI/mesh/MCP/tests/docs) and "content migration" (demo decks, training curriculum). This turn executed both, since "update all documentation" necessarily includes both to be internally consistent.
- The project's own established convention — used consistently across `.project/prompts/mutations/*` throughout this repo's history — is that historical/point-in-time records (dated demo scripts, dev notes, design-prompt logs, funding/timeline plans) are never rewritten after the fact; only living reference material is kept current. This mutation follows that same boundary (see "What Was Deliberately Left Alone" below).

## What Changed and Why

**1. Code removal.** Deleted `hgai_module_hql/` outright and unwound every place that branched on "hql vs shql": the mesh federation layer (`_query_server`/`execute_dot_refs`/`federated_hql` — the last of which is gone, not just renamed), the MCP tool set (`hgai_query_execute` and friends collapsed from dual-language to SHQL-only), the CLI shell (`query`/`validate` commands removed), and the whole "Query (HQL)" UI screen. The query-result cache — never HQL-specific, since both engines always shared `hgai.core.cache`/the `query_cache` collection — got its REST endpoint relocated to `/shql/cache/invalidate` rather than deleted, so cache-flushing functionality wasn't lost in the process.

**2. Documentation rewrite, not just search-and-replace.** Almost every file needed more than swapping "HQL" for "SHQL" text, because HQL and SHQL are structurally different languages (`match`/`where`/`return` vs. `where:` patterns + `select:`), so every embedded query example had to be re-authored, not just relabeled. Two categories of *pre-existing* staleness surfaced repeatedly while doing this and got fixed as part of the same pass, since leaving them would have meant shipping "updated" docs that were still wrong:
   - **The inferencing story was out of date almost everywhere it appeared** (README, concepts.md, the demo-alpha deck, the training curriculum): multiple docs described SKOS/inverse-edge inferencing as either "planned" or driven by a `RelationType.attributes.inverse` field, and one deck explicitly claimed inferencing was "not yet wired into HQL, SHQL, the REST API, or MCP tools." All of this predates work done earlier *this same session* (and a `20260817` mutation before it) that actually built and wired up the real mechanism: control-vocabulary axiom hyperedges (`owl:transitive`, `owl:symmetric`, `owl:inverse-of`, `skos:broaderTransitive`/`narrowerTransitive`) behind `infer: true`, live in SHQL today. Every inferencing section touched was rewritten to match this real design — directly answering the user's explicit "improved documentation for... inferencing" ask.
   - **`EdgeFlavor` has only ever `hub` and `symmetric` today**, but the README, `docs/concepts.md`, the training curriculum, and one demo's import data (`docs/decks/demo-alpha/data/acme-eng-import.yaml`, using `flavor: direct` on 8 edges) all still referenced retired values (`direct`, `transitive`, `inverse-transitive`). The import file would have failed Pydantic validation on next use — a real functional break, not just stale prose — so it was corrected to `flavor: hub` (semantically identical for a 2-member edge) alongside the prose fixes.

**3. Filled two pre-existing documentation gaps while in the neighborhood.** `docs/api-reference.md` had an `## HQL Query` section but no SHQL section at all — a gap noted in this session's very first HQL-vs-SHQL assessment. `docs/concepts.md` was the same: full HQL query-language coverage, zero SHQL coverage. Both gained proper SHQL sections rather than just losing their HQL ones, which is a direct, independent instance of "improved documentation for SHQL."

**4. A broken test, found and fixed.** `tests/test_mesh.py` imported `federated_hql` at module level — deleting that function without touching the test would have broken collection for the *entire* test file, not just the two tests using it. Retargeting those two tests to `federated_shql` surfaced a second, pre-existing bug in the test itself (mocking `httpx.AsyncClient` directly instead of the shared `get_http_client()` singleton the current architecture actually uses, plus an empty `graphs: []` fixture triggering an unmocked live-shaped HTTP call) — fixed alongside the rename rather than left broken under a new name. Full suite: 73 passed, 2 pre-existing-and-unrelated `ping_server` mock failures remain (confirmed via `git stash` diff against `main` before this session's work began).

**5. Live-verified, not just read-verified.** Stood up a disposable MongoDB + server instance twice during this work: once mid-way to prove the SHQL `aggregate` port and an inference-gating fix (already captured in an earlier mutation this session), and again at the end of this task specifically to confirm the *removal* — server boots with `SHQL module mounted` and no HQL mount line, `/api/v1/query` now 404s, `/api/v1/shql/*` and the relocated cache-invalidate endpoint work, the exact example queries printed by the updated `scripts/seed_data.py` run correctly, the MCP `hgai_query_execute` tool works end-to-end, and the UI serves without JS errors. Torn down afterward; nothing persists from either run.

## What Was Deliberately Left Alone
Consistent with this repo's own established convention for historical records:
- **`.project/prompts/**`** — every past ask/mutation capture, including several that themselves discuss or contain HQL. These are point-in-time logs of what was actually asked and done; rewriting them would falsify the record.
- **`docs/dev_notes/*`, `docs/design/*`** (including `prompt-sparql-esque-query-lang.md`, the original prompt that commissioned SHQL) — historical design/decision logs.
- **`docs/operations/timeline-funding-20260817.md`** — an explicitly dated ("Prepared: 2026-08-17"), point-in-time financial planning snapshot.
- **The narrative/prose in `docs/decks/demo-bus-dev-20260817/`, `demo-spec-ops-20260817/`, and `demo-ai-context-memory-20260817/`** — dated records of specific past business-development presentations. Only their `.hql`→`.shql` *filename references* were fixed (mechanical, non-narrative) and their underlying query *files* converted (see below) — the presentation scripts themselves, including embedded `hql:` blocks a presenter would have actually run at the time, were left as an accurate record of what that engagement showed.
- **`notes/**` in its entirety** (`notes/queries.md`, `notes/decks/*`, `docs/decks/demo-alpha/demo-notes.md`) — informal/scratch working notes, not published reference material.
- **`training/user/hgai-user-fundamentals.prompt.md`** — the original specification prompt that generated the training curriculum; a historical record of that request, not something a trainee reads.

One asymmetry worth flagging: the 15 `.hql` query files under the three dated demo decks *were* converted to `.shql` even though their surrounding deck narratives were not. This was a deliberate distinction between a **functional artifact** (a query file that would now simply fail to run — HQL's endpoint no longer exists) and a **historical narrative** (a script describing what was presented and why, on a specific date, in the language that worked at the time). A broken, non-functional file has no value in either a historical or living context; the narrative describing a past event does.

## Key Decisions
- **Full sunset, not a rebrand of HQL text to SHQL text.** Every embedded query example was semantically re-authored, since the two languages have different capabilities (SHQL's `union:` for the `$or`-across-relations case HQL solved via Mongo-operator pass-through; explicit member patterns instead of dot-path `members.node_id` filters). A shallow text swap would have shipped syntactically invalid examples.
- **`docs/decks/demo-alpha` treated as living, not historical**, unlike its `-20260817`-suffixed siblings — it carries no date stamp and reads as the reusable/evergreen onboarding demo (mirrored by its query-file naming convention, which the other decks also follow). Its Phase 4–10 structure was reworked in place (same phase count, same task numbering) rather than deleted, since removing a phase would have cascaded into renumbering ~15 cross-references throughout an 819-line file for no real benefit — repurposing Phase 4 to teach SHQL's simple-filter shape (building toward Phase 6's join shape) preserved the deck's pedagogy while removing the two-language framing entirely.
- **Cache invalidation relocated, not dropped**, since `hgai.core.cache`/the `query_cache` collection were never HQL-specific — deleting the endpoint alongside the HQL module would have been a silent capability loss unrelated to the actual ask.
