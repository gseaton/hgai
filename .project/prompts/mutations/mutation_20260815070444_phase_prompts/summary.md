# Mutation Summary

## Intent
Following the previous session's `build-plan.md` (a greenfield rebuild plan for HypergraphAI v2, written for an AI coding agent to consume), the user wanted the plan's phased roadmap (§14, Phase 0–12) turned into actual, submittable prompt text — not just a description of what each phase should accomplish, but the literal prompts a human would paste into Claude Code (or Cursor/Codex) one at a time to drive the build.

## Context
- `build-plan.md` already fully specifies each phase's goal, deliverables, and exit criteria in prose/table form (§14), plus a defect-avoidance table (§2), tech decisions (§3), data model (§5), query-layer spec (§6), API surface (§7), security model (§8), inferencing design (§9), retrieval design (§10), eventing design (§11), MCP tool table (§12), and testing strategy (§13). This session's job was to compile all of that into 13 self-contained, copy-pasteable prompts — not to design anything new.
- The user's message referenced the path `/docs/design/epics-to-build-production-hgai/build-plan.md` — with "epics" spelled correctly this time, differing from the folder actually created in the prior session (`epcis-to-build-production-hgai`, a typo). Since the referenced file didn't exist at the "epics" path, and "epics" is clearly the intended word (the doc's content is organized as build phases/epics), the directory was renamed rather than creating a duplicate — both directories were untracked (never committed), so a plain `mv` was safe with no git history to preserve across two paths.

## What Changed and Why
- Renamed `docs/design/epcis-to-build-production-hgai/` to `docs/design/epics-to-build-production-hgai/` to match the path the user specified and fix the original typo. `build-plan.md`'s content is unchanged.
- Created `docs/design/epics-to-build-production-hgai/hgai-v0.2-plan-prompts.md` containing:
  - A short "Setup" section instructing the human operator to copy `build-plan.md` into the new greenfield repo at a fixed path (`docs/design/build-plan.md`) before starting, since every phase prompt assumes that path is readable by the agent.
  - 13 prompts (Prompt 0–12), each mapped 1:1 to `build-plan.md`'s Phase 0–12. Each prompt: tells the agent to read the full build plan first, states which prior phases are assumed complete, restates that phase's concrete deliverables and exit criteria inline (so the prompt is useful even if the agent's plan-file read is imperfect or partial), and repeats the specific defect-avoidance callout from §2 that's most relevant to that phase (e.g. Phase 1's prompt stresses zero MongoDB syntax outside the Mongo backend package; Phase 6's prompt stresses the member-anchor-resolution regression test; Phase 9's prompt stresses correct async mock wiring for httpx).

## Key Decisions
- **One prompt per phase, not one giant prompt** — matches how the user said these are meant to be submitted ("in multiple steps... to submit to Claude Code"), and keeps each agent session's working set bounded to one vertical slice, consistent with `build-plan.md`'s own phase-by-phase exit-criteria structure.
- **Each prompt restates its deliverables and exit criteria inline** rather than just saying "do Phase N from build-plan.md" — since these prompts may be submitted as fresh agent sessions with no memory of earlier sessions, and even the build-plan doc read at the start of a session is not a substitute for having the concrete scope in the prompt itself. This trades some token count for reliability, judged as the right tradeoff for prompts meant to actually drive unattended-ish agent execution rather than just for human reference.
- **Each prompt calls out its most relevant defect from §2 by name** (not just "avoid past mistakes") — e.g. explicitly naming the MagicMock-vs-AsyncMock failure mode in the mesh-federation prompt — because these were the specific, concrete failure modes found in the reference implementation audit, and generic "write good tests" guidance was judged less effective than naming the exact anti-pattern to avoid.
- **Renamed the folder rather than duplicating content** at both spellings — there was no reason to keep the typo path once the correct one was established, and since neither had been committed yet there was no history-preservation concern.
