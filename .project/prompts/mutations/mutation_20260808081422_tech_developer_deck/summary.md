# Mutation Summary

## Intent
Third deck in this session's series, following the investor/funding deck (`hgai-investor.md`) and the architecture/adoption-decision deck (`hgai-tech-architect.md`). This one targets a different audience with a different job to be done: AI software engineers who need to actually *write code* against HypergraphAI, not evaluate whether to adopt it or fund it. The brief was explicitly "how to implement / leverage," i.e. a hands-on cookbook, and specified an exact dated filename (`notes/decks/hgai-tech-developer-20260808.md`).

## Context
- By this point in the session, the codebase's query languages, MCP surface, member-`seq` positional filtering (implemented earlier in this session), federation, and honest capability gaps were all already deeply verified from the prior two decks and the earlier engine-refactoring work — this deck reuses that grounding rather than re-deriving it.
- Consistent with the pattern established across all three decks this session: verify claims against source before writing them, rather than reusing assumed-correct phrasing. Two concrete corrections were made specifically for this deck, caught by reading the actual FastAPI request models rather than guessing endpoint shapes:
  - The Python client wrapper (Slide 4) and a validate `curl` example (Slide 12) originally used a JSON body key of `"query"` for `POST /api/v1/query`; reading `hgai_module_hql/api_router.py`'s `HQLRequest`/`HQLValidateRequest` Pydantic models showed the actual field name is `"hql"`. Both examples were corrected.
  - The cheat sheet (Slide 17) originally listed only the HQL REST endpoints. Reading `hgai_module_shql/api_router.py` confirmed SHQL has its own separate endpoints (`POST /api/v1/shql/query`, `POST /api/v1/shql/validate`) with a `"shql"` body key — added to the cheat sheet since the deck uses SHQL recipes heavily but had never actually shown how to call it over REST.
- Also verified before writing: `HGAI_RELOAD` env var and `--mongo-connection` CLI flag (both against `hgai/config.py`/`hgai/main.py`), the exact `hgai-shell` command set (against `README.md`'s shell reference), and the Docker Compose vs. local-CLI port discrepancy (8000 vs. 8357) — surfaced explicitly as a gotcha rather than silently picking one and risking a copy-paste failure for a reader using the other path.
- Confirmed there is no bundled Python SDK/client library in the repo (only `shell/hgai_shell.py`, a CLI tool, not an importable client) — stated this directly in Slide 3 rather than implying one exists, and the deck's own Python examples are framed as "the wrapper you'll write yourself," not as calling an existing library.

## What Changed and Why
- **Created `notes/decks/hgai-tech-developer-20260808.md`** as a new, third file, distinct from both prior decks — no funding/market content (unlike the investor deck) and no architecture-decision/security-review framing (unlike the tech-architect deck); purely implementation recipes.
- Structured as 18 slides moving from a 60-second mental model → quickstart → integration path selection → a real client code wrapper → schema design → write-path recipe → HQL cookbook → SHQL cookbook → temporal recall → the recall/act/record agent-loop pattern → MCP wiring → testing/validation → a gotchas table → federation → local dev loop → performance tips → a condensed cheat sheet → further-reading pointers (linking to `README.md`, `docs/api-reference.md`, `docs/module-development.md`, the existing `docs/decks/demo-alpha/` demo, and this session's own `hgai-tech-architect.md`).
- The gotchas table (Slide 13) and the temporal-recall slide's "known limit" callout (Slide 9, noting `hgai/core/inference.py`'s transitive walk doesn't thread `pit` — a gap identified during this session's earlier inference-engine research) continue the same policy from the prior two decks: name specific, verified limitations a developer would otherwise discover by trial and error, rather than presenting only happy-path recipes.
- The agent-loop code pattern (Slide 10) and MCP wiring example (Slide 11) directly demonstrate the write-then-recall memory pattern that is the stated purpose of adopting HypergraphAI for agentic systems — this was treated as the deck's centerpiece rather than one recipe among many, since "how do I actually leverage this for agent memory" was the specific ask.

## Key Decisions
- **Verified request-body field names against the actual FastAPI request models rather than inferring them from prior context**: this session had extensively used HQL/SHQL YAML *content* but had not previously needed the REST wrapper's exact JSON field name — reading the router source directly (rather than assuming `"query"` by analogy to common conventions) caught a real bug in the drafted examples before they were finalized.
- **Explicit "no bundled SDK" framing** instead of writing example code that implies a library ships with the project: judged more useful and more honest for engineers who will actually try to `pip install` something based on the deck's code samples.
- **Treated the port discrepancy (8000 vs 8357) as a gotcha worth a callout**, not a detail to silently normalize to one number — a developer copy-pasting a command against the wrong running instance is exactly the kind of low-value confusion this deck's whole premise (accurate, checked-against-code content) is meant to prevent.
