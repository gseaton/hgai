# Mutation Log

## Modified
- **hgai/core/inference.py** — `project_inference()` gained a `dry_run: bool = False` parameter and a richer return shape: every candidate is now tagged into a `preview` list with `status` ("new", "skip", or "error"), its relation/members/provenance fields, and (once written) its real edge id or (if a duplicate) the existing edge's id. `dry_run=True` computes the full result — including which candidates already exist — without writing anything at all, not even a new target hypergraph document. Return shape is now `{created, skipped, errors, error_details, edges, preview, dry_run}`.
- **hgai/api/routers/inference.py** — `ProjectInferenceRequest` gained `dry_run: bool`; `ProjectInferenceResponse` gained `preview: List[dict]` and `dry_run: bool`. The route skips creating the target hypergraph (even when `create_target: true`) when `dry_run` is set, and passes `dry_run` through to `project_inference`.
- **ui/js/api.js** — Added `projectInference(targetGraphId, data)` calling `POST /graphs/{targetGraphId}/infer/project`, exported from the `HGAI_API` module.
- **ui/index.html** — New "Project Inference" nav link and `#screen-project-inference` screen: source hypergraph(s) multi-select, mode checkboxes (Expand axioms / Transitive closure) with a relation text input and optional point-in-time field, target hypergraph picker (existing-graph dropdown or new-graph id/label fields), Preview and Confirm & Project buttons, and a results section (summary badges + a card list of every candidate with its status).
- **ui/js/app.js** — `loadProjectInferenceScreen()` (populates the source multi-select and target dropdown, invoked by the screen router); `updatePiTargetFieldVisibility()` (toggles existing-vs-new target fields); `piBuildRequest()` (validates the form, builds the API request, combining the two mode checkboxes into the single `mode` string the backend expects); `piStatusBadge()`/`piRenderPreview()` (render the summary + per-candidate card list); Preview and Confirm & Project click handlers. The commit button is disabled by default and re-disabled on any form change — it only re-enables after a fresh Preview whose exact request matches what would be committed, so nothing can be projected without first being shown to the user.
