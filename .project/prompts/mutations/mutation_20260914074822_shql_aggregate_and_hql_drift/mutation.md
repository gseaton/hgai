# Mutation Log

## Modified
- **hgai_module_shql/engine.py** — Ported `aggregate`/`group_by` onto SHQL: added `aggregate = shql.get("aggregate", {})` field read in `execute_shql`, and an aggregate-computation block inserted after DISTINCT dedup / before ORDER BY (computed over the full matched, deduplicated item set, pre-pagination), spreading `**agg_results` into the response `meta` — mirrors `hgai_module_hql/engine.py`'s `count`/`group_by` logic line-for-line. Also fixed a pre-existing gating bug in `_eval_edge_pattern`: axiom expansion (`expand_edge_closure`) was gated on `if infer and resolved_rel:`, silently skipping inference for any edge pattern with no `relation:` filter (e.g. "all hyperedges, all relations"), even though `expand_edge_closure` itself is relation-agnostic. Changed to `if infer:`, moving the `resolved_rel` requirement down to just the transitive-reachability sub-check (`if resolved_rel and len(member_patterns) == 2 and ...`), which is the only part that actually needs a concrete relation. This fix was required for item 3 below to work at all.
- **hgai/main.py** — Added `"shql"` to the `/api/v1/server/info` `capabilities` list (previously listed `"hql"` but not `"shql"`).
- **README.md** — Removed the Roadmap bullet "HQL `infer:` clause — explicit inference directives inside HQL queries (e.g., `infer: transitive`)" (already shipped, and describing a syntax — `infer: transitive` — that doesn't match what shipped — `infer: true`). Updated the `### HQL vs SHQL` comparison table: added an "Aggregation" row (now Yes/Yes) and removed "aggregations" from HQL's "Use when" cell, adding it to SHQL's. Added `infer:` and `aggregate:` entries (with an explanatory comment on `group_by`'s row-key semantics) to the SHQL `### Language Structure` documented YAML block, which was otherwise exhaustive.
- **ui/js/app.js** — Added a new `'Aggregate: count by relation'` entry to `SHQL_EXAMPLES`. Rewrote `fetchInferredEdges(graphId)` (used by the 3D viz's "Show inferred edges" checkbox) from a hand-built HQL query string (`HGAI_API.runQuery`) to an equivalent SHQL query (`HGAI_API.runShqlQuery`) — `where: [{edge: ?edge}]`, `infer: true`, `select: [?edge]` — with the result-parsing updated from flat HQL items to unwrapping the `?edge`-keyed SHQL row (`row.edge`) before the existing `_inferred` filter and synthetic-id mapping. Updated the surrounding comment block accordingly.

## Not modified (considered, explicitly out of scope)
- `hgai_module_shql/parser.py` — no structural validation added for `aggregate`, matching the fact that HQL's `validate_hql` doesn't validate it either.
- `docs/api-reference.md` — has no SHQL section at all (pre-existing gap, unrelated to this change); not created here.
