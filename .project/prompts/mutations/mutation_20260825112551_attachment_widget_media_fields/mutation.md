# Mutation Log

## Modified
- **ui/js/app.js** — `renderMediaList()` (the shared node/edge "associated media" attachment widget) now renders: primary text = `ref.label || ref.filename || ref.media_id`, a muted secondary line for `ref.name` (only when present and different from the primary text), a content-type badge, and a size/duration badge (via the previously-added `mediaSizeDurationText()` helper) — both badges only render when the underlying data is present, so refs attached before this change (which lack the newly-cached fields) degrade gracefully instead of showing empty/placeholder badges. `handleMediaUpload()` and `attachExistingMedia()` now cache `name`, `label`, `size_bytes`, `duration_seconds` onto the `MediaRef` at attach time (mirroring how `content_type`/`filename` were already cached), sourced from the just-uploaded or picker-selected `Media` record. `openMediaRefEditModal()` and the attachment widget's Preview button now also prefer `ref.label` over `ref.filename` for display, consistent with the rest of the app.
- **ui/css/hgai.css** — Added `.media-item-text` (a column-flex wrapper so the primary/secondary text lines stack inside the existing single-row `.media-item` layout) and `.media-item-subname` (smaller, muted styling for the name subtitle line).
