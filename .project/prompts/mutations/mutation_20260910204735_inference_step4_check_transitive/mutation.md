# Mutation Log

## Modified
- **hgai/core/inference.py**
  - `walk_closure()` return type changed from `Dict[str, str]` (reached node → via-edge-id) to `Dict[str, Tuple[str, str]]` (reached node → `(via_edge_id, predecessor_node_id)`), so a full path back to the start node can be reconstructed by following predecessors. Updated its one existing caller in `expand_edge`'s superproperty-projection block to unpack the new tuple shape.
  - Removed `check_transitive_relation()` (superseded — zero callers, boolean-only, no PIT support, its own separate inline BFS). Added `check_transitive(relation, graph_ids, start_id, end_id=None, mode="bool"|"closure"|"path", max_depth=10, pit=None)`, rebuilt on `walk_closure`: self-verifies the relation actually carries an `owl:transitive` axiom before walking anything (mirroring `expand_edge`'s own axiom-checking pattern rather than trusting the caller); `mode="bool"` returns whether `end_id` is reachable; `mode="closure"` returns every node transitively reachable from `start_id`; `mode="path"` returns the ordered list of hyperedge ids connecting `start_id` to `end_id` by following predecessors backward.
  - Updated module docstring: both `expand_edge`/`expand_edge_closure` and `check_transitive` are now wired into HQL behind `infer: true`.
- **hgai_module_hql/engine.py** — `execute_hql()`: when `infer: true` and the hyperedge match gives both `relation` and `nodes`, additionally runs transitive-closure reachability alongside the existing `expand_edge_closure` call — one node in `nodes:` triggers closure mode (one synthesized `_inferred`/`_transitive`-tagged edge per newly-reachable node); exactly two nodes triggers path mode (one synthesized edge carrying the ordered `_transitive_path` of hyperedge ids). Both modes skip 1-hop results, since a node reachable in exactly one hop is definitionally already a literal stored edge and would otherwise duplicate an item already present in the plain (non-inferred) match results.
- **tests/test_inference.py** — No `walk_closure`/`check_transitive` unit tests added (both are DB-dependent; verified live per this session's established pattern) — existing pure-function tests unaffected by this change.
