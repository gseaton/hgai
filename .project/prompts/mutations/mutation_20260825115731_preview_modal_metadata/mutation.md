# Mutation Log

## Modified
- **hgai/models/media.py** — Added `description: Optional[str]` to `MediaRef`, alongside the `name`/`label`/`size_bytes`/`duration_seconds` fields already cached there, so the attachment-widget preview entry point has full metadata available without a round-trip.
- **ui/index.html** — `modal-media-preview`'s body now contains, below the image/audio/video player, a metadata table with Name, Label, Size, Duration, and Description rows (previously the modal showed only a title derived from filename/label and the player itself).
- **ui/js/app.js** — Refactored `openMediaPreview()` from four positional parameters (`mediaId, filename, contentType, label`) to a single `info` object (`{ id, filename, content_type, name, label, description, size_bytes, duration_seconds }`), since the field list had grown too large for positional args to stay readable. Added `renderMediaPreviewMetadata(info)` to populate the new metadata table (size via `fmtBytes`, duration via `fmtDuration(...) || '-'`, everything else via `textContent` with a `—` fallback). Added `mediaToPreviewInfo(m)` to build that `info` object from a full `Media` record, used at the two call sites that have one (the standalone Media catalog's preview button, the "Browse Existing" picker's preview button); the third call site (the node/edge attachment widget) builds it directly from the `MediaRef`, now including the newly-cached `description`. `handleMediaUpload()` and `attachExistingMedia()` now also cache `description` onto the `MediaRef` at attach time, alongside the fields already cached there.
