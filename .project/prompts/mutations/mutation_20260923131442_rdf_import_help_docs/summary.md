# Mutation Summary

## Intent
RDF import has grown substantially over this project's recent history — full prefix expansion, OWL axiom-edge synthesis (`owl:transitive`, `owl:inverse-of`, `owl:symmetric`), and a digit/quote-led literal-value classification rule (numbers vs. text, with a `-1` fallback for malformed numeric-looking values) — but none of that had a dedicated Help topic, and README.md had no mention of RDF import at all (not in the table of contents, not in the Web UI section, not in the shell command reference). The user asked for Help topics covering RDF import's concepts, examples, and caveats, plus a README update.

## Context
The existing `docs/help/notes/web-ui/export-import.md` topic already carried a condensed RDF mapping table (built up incrementally across several earlier sessions covering OWL axioms and the digit/quote literal rule), but it's a shared topic whose main subject is native hypergraph export/import — RDF import is one section within it, sized for a quick reference, not a deep dive with worked examples. The Help system (`hgai/core/help.py`) treats every `*.md` file under `docs/help/notes/` as a topic, keyed by a `help-<name>` id in YAML front matter, cross-linked via `[text](help:help-other-id)`; topics are organized into virtual folders via `//Folder/Path` tags (see [[rdf-owl-symmetric-axiom-edge]] and prior RDF-import mutations for the underlying feature's own history). Separately, the interactive shell (`shell/hgai_shell.py`) already has a working `import-rdf` command that had never been documented anywhere — a pre-existing gap unrelated to the RDF-mapping feature itself, discovered and fixed as part of this pass.

## What Changed and Why
Created `docs/help/notes/web-ui/rdf-import.md` (`id: help-rdf-import`) as the dedicated deep-dive: a **Concepts** section walking through the full mapping model (id expansion and why attribute keys are the one exception, `rdf:type`/label handling, the literal digit/quote-led value classification rule, resource-valued triples becoming hyperedges, and the three recognized OWL axioms), a **Worked examples** section with four concrete TTL-to-hypergraph-document examples (including one exercising the `owl:symmetric` axiom and its interaction with `infer: true`), and a **Caveats** section split into genuinely unhandled RDF features (Collections, JSON-LD named graphs, reification, other OWL/RDFS axioms) versus behavior that's correct but easy to be surprised by (a quoted numeric-looking string still becoming a number, the `-1` fallback, bare dates staying text, attribute keys never expanding, type-only classes getting no node).

The existing `export-import.md` topic was left as the condensed quick-reference it already was, with one added sentence pointing to the new deep-dive topic — avoiding duplicating the full mapping model in two places. `home.md` and `glossary.md` got small additions so the new topic is discoverable from the two main entry points (the landing page's curated link list, and glossary lookups for "RDF import" / "CURIE"). `shell.md` and `export-import.md`'s shell examples both gained the previously-undocumented `import-rdf` command.

README.md received a new top-level `## RDF Import` section (mirrored from the new Help topic's mapping table, condensed for a single README section) placed after `## Web UI` and before `## Inferencing` — RDF import feeds directly into inferencing via the OWL axiom edges, so that ordering lets a reader go straight from "how RDF becomes hyperedges" to "how those hyperedges get reasoned over." The table of contents, the Web UI section's Hypergraphs bullet, and the shell command block were all updated to reference it consistently.

## Key Decisions
- Created a **new, separate** Help topic rather than expanding `export-import.md` in place, because the RDF mapping model (identity rules, literal classification, three OWL axioms, several worked examples, and a caveats list) is substantial enough to overwhelm a topic whose primary subject is native export/import — splitting keeps each topic's scope focused, consistent with how this Help tree already splits SHQL into overview/patterns/filters/examples rather than one large page.
- Put the OWL-symmetric worked example in the new topic (not just the mapping table) specifically because it demonstrates the two-hyperedge interaction with `infer: true` end-to-end, which a table row alone can't convey.
- Documented `import-rdf` in three places (`shell.md`, `export-import.md`'s shell block, and README's shell command block) rather than just one, since all three already listed the sibling native `import`/`export` commands and would otherwise now be visibly inconsistent — a reader following any one of them needs to see the same command exists.
- Placed README's new `## RDF Import` section between Web UI and Inferencing (not, say, immediately after Quick Start) to preserve the document's existing progression from "how to use it" (Web UI, this new section) into "what it enables" (Inferencing, SHQL) rather than interrupting the earlier setup-focused sections.
