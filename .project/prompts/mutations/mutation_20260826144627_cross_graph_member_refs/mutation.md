# Mutation Log

## Modified
- **hgai/models/hyperedge.py** — `EdgeMember.node_id`'s field description now documents the new `graph_id.` prefix convention (e.g. `bravo.person:john`), matching HQL/SHQL's `from:` dot-notation. No schema/validation change — `node_id` was and remains an unconstrained string; this is a documentation-only update since interpretation happens entirely at the point of use (the 3D visualization).
- **ui/js/app.js** — Added `vizParseMemberRef(nodeId)`, which splits a member `node_id` on its first `.` and treats the prefix as a target `graph_id` only when it names a graph the app already knows about (`State.graphsCache`) — otherwise the id passes through unchanged, so any pre-existing id with a literal `.` keeps resolving locally exactly as before. Rewrote `renderViz()`'s node/edge-building into three phases: (1) fetch each selected graph's own data as before; (2) resolve every graph-qualified member reference found anywhere via a single-item `GET` against its target graph (trying hypernode first, then hyperedge), independent of whether that target graph is itself selected for viewing; (3) build the scene in two passes — Pass A pushes every directly-selected graph's own hnodes/henodes unconditionally (unchanged from before), Pass B builds each hyperedge's members-node and relation links, lazily materializing any still-missing target (a genuine cross-graph reference, or a same-graph node the orphan-hiding toggle skipped) as a leaf node tagged `crossGraph: true` — deduplicated by id so a target that's also part of a directly-selected graph is never double-created, and a link is only ever emitted once its target definitively exists. A cross-graph hyperedge target's own member structure is intentionally not expanded (only the referenced node/hyperedge identity itself is visualized). Updated `initViz3D()`'s node tooltip and `vizBuildLabelLayer()`'s on-screen label to show an explicit origin-graph note/suffix for `crossGraph` nodes, and to skip the now-misleading member-count text for a cross-graph hyperedge stub. Replaced the `hyperedgeCount` running counter with a direct `nodes.filter(n => n.kind === 'henode').length` at render-stats time, since hyperedge nodes can now originate from either the main per-graph loop or a cross-graph resolution.
- **ui/css/hgai.css** — Added `.viz-label-node-external`, a dashed-amber variant of `.viz-label-node` applied to any node's on-screen label when it's a cross-graph reference, so it's visually distinguishable from the current graph's own nodes at a glance.
