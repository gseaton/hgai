# Mutation Log

## Modified
- **ui/js/app.js** (`renderViz()`) — Added a second id-space (`hedgeIdSet`, built from every hyperedge's `id`/`hyperkey`) alongside the existing hypernode `nodeIdSet`. Added `vizMemberTargetId(nodeId)`, which resolves a member's `node_id` against both sets and returns the correct viz-graph node id for whichever kind it is (`${gid}::${id}` for a hypernode's `hnode`, `${gid}::he::${id}` for a hyperedge's `henode`), or `null` if it resolves to neither. Member filtering (`validMembers`) now uses this resolver instead of only checking hypernode ids, and the relation-links built from each hyperedge's "members" virtual node use the resolved target id rather than always assuming a hypernode. A hyperedge's own `henode` is now always created (even with zero currently-resolvable members) — previously the whole hyperedge was skipped and never added to the graph at all if none of its members were hypernodes, which meant a hyperedge that only had *other hyperedges* as members was completely invisible and any link pointing at it would have been dangling.
