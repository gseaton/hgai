# Mutation Log

## Modified
- **hgai/core/engine.py** — Added `_normalize_hyperkey_instant()` to canonicalize a `datetime` (or `None`) for hashing (UTC-normalized ISO format; naive datetimes treated as UTC; `None` stays `None`, never conflated with an empty string). Extended `generate_hyperkey()` with optional `valid_from`/`valid_to` parameters, folded into the hashed payload alongside relation/members/graph. Updated `create_hyperedge()` to pass `doc.get("valid_from")`/`doc.get("valid_to")` into the hyperkey computation. Updated `update_hyperedge()`'s hyperkey-recompute block to resolve `valid_from`/`valid_to` from the patch (falling back to the existing edge's values, same pattern already used for `relation`/`members`) and pass them through. Added `find_duplicate_hyperedge()`, a new public helper that computes what a new hyperedge's hyperkey would be and looks up any existing edge already holding it, for use by API routers before insert.
- **hgai/api/routers/hyperedges.py** — `create_edge()`: after the existing `data.id` collision pre-check, added a second pre-check via `engine.find_duplicate_hyperedge()` that raises a clean `409` ("An identical hyperedge (same relation, members, and validity window) already exists as '<id>'...") instead of letting an exact-duplicate hyperkey fall through to a raw, uncaught pymongo `DuplicateKeyError` at insert time.
- **hgai/api/routers/spaces.py** — `create_space_edge()`: same pre-check added for the space-scoped hyperedge-creation endpoint, for parity with the unowned-graph endpoint.
- **tests/test_engine.py** — Added `datetime`/`timezone` import and five new tests: same relation/members/graph but different validity windows produce different hyperkeys (the core ask — "same lineup, two eras"); identical relation/members/window still collides (still correctly rejected as a true duplicate, member order included); an unbounded window (`None`/`None`) is a distinct identity from any explicit bounded window; and the same instant expressed as UTC / a different timezone offset / a naive datetime all normalize to the same hyperkey.
