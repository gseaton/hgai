# Mutation Summary

## Intent
Let an imported RDF/OWL ontology's own transitivity and inverse-property declarations become usable by HypergraphAI's `infer: true` reasoning immediately on import, instead of only round-tripping as inert attributes/edges the way every other RDF construct does.

## Context
`hgai/core/inference.py` never hardcodes which relations are transitive or each other's inverse — it recognizes them from ordinary hyperedges asserting the fixed control-vocabulary strings `"owl:transitive"` and `"owl:inverse-of"` between relation-hypernodes (see `scripts/seeds/hgai-hypergraph-eden.export.yml`'s hand-asserted `edge:child-trans` and `edge:parent-inv-child`). Before this change, RDF import's general rule routed every `rdf:type` triple into node metadata only (never an edge) and every resource-valued predicate into a generic hub edge keyed by the predicate's own expanded IRI — so an ontology's `owl:TransitiveProperty`/`owl:inverseOf` declarations imported as inert data, never as something `infer: true` would act on.

## What Changed and Why
Two narrow, additive exceptions were layered onto the existing general rules, both detected by the real, canonical OWL IRI (`rdflib.namespace.OWL`) rather than by whatever local prefix a source file happens to bind — so recognition doesn't depend on a file using the specific prefix name `owl:`. `owl:TransitiveProperty` synthesizes an *additional* single-member axiom edge alongside the property's normal `rdf:type` handling (which is unaffected). `owl:inverseOf` reuses the exact same resource-edge code path every other object-property triple already goes through — subject seq 0, object seq 1 — with only the `relation` string swapped to HypergraphAI's fixed `"owl:inverse-of"` spelling instead of the predicate's real (differently-spelled, unhyphenated) IRI, since the inference engine matches that string exactly.

## Key Decisions
- **Detected by canonical OWL IRI, not by a hardcoded prefix string.** Using `rdflib.namespace.OWL.TransitiveProperty`/`OWL.inverseOf` means a file that binds the OWL namespace to any local prefix (`owl:`, `o:`, no prefix, ...) is recognized identically — verified directly with a test using a `o:` prefix.
- **Additive, not a replacement, for `owl:TransitiveProperty`.** The property still gets its ordinary `type`/`attributes.rdf_type` from the ontology's ordinary rdf:type handling (unchanged); the axiom edge is emitted alongside it, not instead of it.
- **`edge_tuples`'s shape was generalized (fixed pair -> variable-length tuple) rather than adding a second, parallel list for single-member edges** — keeps one sort/build code path for every edge kind (ordinary object-property, `owl:inverse-of`, `owl:transitive`), rather than two similar-but-separate ones that could drift apart.
- **Verification, in order:** (1) direct output check against both examples from the request, byte-for-byte; (2) 8 new unit tests plus the full 73-test RDF suite, mutation-tested (temporarily disabling both new rules) to confirm 5 tests would actually catch a regression, restored via `diff` against a saved copy rather than `git checkout` (a destructive-command mistake from the *previous* turn's investigation that this turn deliberately avoided repeating); (3) live, functional, end-to-end proof on a disposable server instance — not just checking the document shape, but actually running `infer: true` SHQL queries and the `/infer/transitive` endpoint against RDF-imported data with a real transitive chain (cain→adam→eve) and confirming both the transitive closure (cain reaches eve) and the inverse-of derivation (including the *doubly*-derived fact — inverse-of applied to a transitively-derived edge — eve→cain `hasChild`) come out correctly, proving the axiom edges are treated identically to hand-asserted ones, not just shaped like them. Test data and the disposable instance were cleaned up afterward. Full project suite: 527 passed (2 pre-existing, unrelated mesh-ping failures excluded, as in every run this session).
