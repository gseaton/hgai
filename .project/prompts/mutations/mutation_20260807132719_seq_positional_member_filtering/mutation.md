# Mutation Log

## Created
- **tests/test_shql.py** — New test file covering SHQL positional member matching: `seq` matching the correct position, rejecting the wrong position, binding the seq-N member's node_id, and the `_match_members_expand` anchor-classification fix for already-bound `bind` vars combined with `seq`.

## Modified
- **hgai_module_hql/engine.py** — `_build_edge_search_filters` now collects `members.*` sub-field constraints from both the nested `where: {members: {...}}` form and the literal-dotted-key form (`where: {"members.seq": ..., "members.node_id": ...}`) into one merged dict. A single sub-field still becomes a plain `members.<field>` dot-path (unchanged "contains anywhere" behavior); two or more sub-fields together now become a single `members: {"$elemMatch": {...}}` filter, so Mongo binds all conditions to the same array element instead of matching each independently.
- **hgai_module_shql/engine.py** — Added `_resolve_member_pat` (resolves a member pattern's `bind`/`id`/`seq` against the current binding set) and `_member_satisfies` (checks a single edge member against required `id`/`seq`) as shared helpers. `_match_members` now uses these instead of inline `id`-only resolution, adding `seq` filtering. `_match_members_expand`'s anchor/wildcard classification now treats a pattern as an anchor whenever it resolves to a required `id` and/or `seq` — including via an already-bound `bind` variable, which previously fell through to the wildcard path unconstrained (a pre-existing bug: it could silently match/bind the wrong member since the wildcard-expand loop overwrites `bind_var` unconditionally).
- **README.md** — Fixed the `potus-at` HQL example (previously combined `members.node_id: {$all: [nation:usa]}` with `members.seq: 0`, which would now require nation:usa itself to be the seq-0 member — wrong intent); simplified to a single `members.node_id: nation:usa` filter with an explanatory note that HQL can't bind/extract "the other member" and returns the full `members` array for that purpose. Added a note under the SHQL `potus-at` "How it works" table confirming `seq: 0` is now positionally enforced. Updated the "regardless of position" explanation to clarify it only applies to a single member sub-field, with a link to a new subsection. Added a new "Positional member filters (seq)" subsection with a worked example (`seq` + `node_id` combined via `$elemMatch`) and an explanation of the merge/`$elemMatch` translation. Added a clarifying note to the mesh `alpha-bravo-mesh` SHQL example explaining that `seq: 0` now pins `?group` to specifically the hub edge's first member.
- **ui/js/app.js** — Added one new HQL_EXAMPLES entry ("Positional member filter — first member is a specific node (seq)") and one new SHQL_EXAMPLES entry ("Positional member filter — bind the first member (seq)"), both demonstrating the new `seq`-based positional filtering in the query editor's examples panel.
- **tests/test_query.py** — Added tests for `_build_edge_search_filters`: single member field still uses a dot-path (both nested-dict and literal-dot-key syntax), and two member fields (seq + node_id) combine into `$elemMatch` (both syntaxes).
