# Mutation Summary

## Intent
Add a rich, per-account note/document capability to hgai — inspired by the user's separate single-user Markdown note-taking project, Quill — but adapted for hgai's multi-account world with the ability to scope sharing (viewing vs. editing) across accounts, something Quill has no concept of at all (it's file-based, single-user, no auth).

## Context
Before writing any code, the user explicitly asked for 3+ clarifying questions, so the assistant first read Quill's actual feature set (README: Markdown notes with tags, a virtual tag-based folder sidebar, note-to-note linking (`[text](note:id)`) and embedding, a media library referenced inline (`![text](media/label)`), LaTeX, PDF export, a chat panel, workspace tabs) and hgai's existing account/permission model (a flat `AccountPermissions.graphs` allow-list, and a separate, coarser-grained Spaces model with owner/admin/member/viewer roles applying to a whole space's graphs at once — not fine-grained enough for "share this one note with Alice as viewer"). Four questions were asked covering the biggest architecture forks: where a Note lives structurally, which Quill features make the v1 cut, how sharing is scoped, and how deep the UI integration goes. The user picked the recommended option on all four: Notes as a brand-new first-class resource (not a hypernode); Markdown editor+preview, tags+search, Media-subsystem-backed embedding, and note-to-note linking for v1; a per-note ACL (not Spaces) for sharing; and full integration into the existing left-nav UI.

## What Changed and Why
**Storage/model layer**: Notes were built as a peer to Accounts/Spaces/Media — their own MongoDB collection, storage-backend abstraction (`NoteStore` ABC + `MongoNoteStore`), and Pydantic models — rather than shoehorned into the hypernode/hyperedge shape, since a personal document isn't naturally an N-ary graph fact, and Quill's own flat shape (label/tags/text) was exactly the better fit the first clarifying answer confirmed.

**Sharing**: Implemented as a literal `acl: List[{username, role}]` field directly on the Note document, with the owner always implied to have full access (never listed in the ACL itself). `viewer` grants read-only; `editor` grants content edits but not sharing or deletion, which stay owner-only — mirroring the mental model of "the owner delegates capabilities, doesn't hand over ownership." Idempotent re-sharing (same user, same role) produces no new audit-trail entry, matching the project's established "no redundant sequential mutations" convention from earlier in this session's work on hypernode/hyperedge mutation tracking — reused here via a small, necessary refactor (see below).

**Mutation audit trail reuse, and the bug it surfaced**: Rather than reimplementing "track who changed what and suppress redundant repeats" a third time, the existing `_create_delta`/`_update_delta`/`_append_mutation` helpers (built earlier this session for hypernodes/hyperedges) were extracted out of `hgai/core/engine.py`'s file-private scope into a new shared `hgai/core/mutations.py` module, since importing another module's underscore-prefixed "private" functions directly would have been a real code smell. `engine.py` re-imports them under their original names so no existing call site or test needed to change. Live verification against a real server caught a genuine bug this refactor's careful separation didn't automatically prevent: `share_note`/`unshare_note`/`update_note` initially passed `existing.mutations` (a list of `MutationRecord` *model instances*) into `append_mutation`, which calls `.get()` expecting plain dicts — exactly the same "dump to a plain dict first" step `update_hypernode` already does via `existing_dump = existing.model_dump()`, which this code had initially skipped. Fixed by pulling `mutations` from `existing.model_dump()` everywhere, matching the established pattern.

**Media embedding and note linking**: Rather than building custom Markdown-rendering machinery tied to a specific library's renderer-override API (which differs across `marked.js` major versions and would be fragile to depend on), embed/link resolution is done via a version-independent plain-text placeholder swap: `![alt](media:<id>)` and `[text](note:<id>)` are regex-extracted from the raw Markdown *before* handing it to `marked.parse()`, replaced with inert alphanumeric placeholder tokens, and — after `marked.parse()` + `DOMPurify.sanitize()` — swapped back out for hand-built, `escapeHtml()`-escaped HTML (a real `<a>` for a resolved note link styled distinctly when broken, or an `<img>` placeholder for a media embed that's then asynchronously resolved to an authenticated blob URL, exactly mirroring the existing `downloadMedia()`+`createObjectURL()` pattern already used for media thumbnails elsewhere in this app). This keeps DOMPurify as the sole XSS trust boundary regardless of what `marked` does internally, while still supporting custom link schemes cleanly.

**UI**: The Notes screen (list + editor + share modal) was built to visually and interactively match the existing Hypernode/Hyperedge/Media screens exactly — same table/pagination/search-bar conventions, same section-based modal layout, same read-only History section reusing `renderMutationHistory()` unchanged, and the exact same Media-attachment widget (`renderMediaList`, upload/attach, browse-existing-media picker) hypernodes and hyperedges already use, extended with a `null`-returning case in `defaultMediaState()` so the "set as default representation" star toggle is cleanly omitted for notes (which have no `default_media_id` field) without every existing call site needing to learn a new parameter.

## Key Decisions
- **New first-class resource, not a hypernode type** — per the user's explicit, recommended choice; keeps a note's lifecycle and access model independent of hypergraph-specific machinery (hyperkey dedup, graph-scoped permissions) that doesn't apply to a personal document.
- **Per-note ACL, not Spaces** — per the user's explicit, recommended choice; enables the exact granularity asked for ("share this specific note with Alice as viewer") that a whole-space membership model can't express.
- **Editor can edit content but not share/delete** — a design choice filling in a gap the clarifying questions didn't explicitly specify: "editor" access naturally means "can change what's in it," not "can change who else has access to it" or "can destroy it," keeping those two more consequential actions owner-only (with an admin override, consistent with every other admin-bypasses-ownership pattern already in this codebase).
- **Regex placeholder-swap over a custom `marked.js` Renderer** — avoids depending on a renderer method signature that has changed across `marked` major versions; works identically regardless of the pinned CDN version, verified by testing an actual redirect/broken-link/media-embed round-trip in the browser rather than assuming the API shape.
- **Note-link resolution scoped to notes visible to the viewer** — since it reuses the same `list_notes_visible_to` visibility filter as the Notes screen itself, a link to a note you can't see resolves as "broken" rather than leaking that note's existence/label — a privacy property that falls out of reusing the existing access-control path rather than needing separate enforcement.
- **Deferred from Quill's larger feature set, disclosed rather than silently dropped**: LaTeX math, PDF export, a chat panel, workspace tabs, and note-embedding-as-transclusion (as opposed to plain linking) were all explicitly out of the four-question scope negotiation and are not built. A "copy embed markdown" convenience button (mirroring Quill's UX nicety) was also skipped for v1 — the `media:<id>`/`note:<id>` syntax works when typed by hand, but there's no one-click helper for it yet.
