# Mutation Log

## Modified
- **hgai/core/rdf_import.py** — Rewrote `_literal_value()` to classify a literal's attribute *value* by the first character of its own lexical form rather than by its RDF/XSD datatype: a lexical string starting with an ASCII digit is now always parsed as a number (`int(s)`, else `float(s)`, else `-1` if neither parses) — even when RDF typed the literal as a plain string (e.g. a quoted `"12345"`). Everything else stays text. Booleans (`xsd:boolean`) and dates/timestamps (`xsd:date`, `xsd:dateTime`) are checked first and exempted from the digit rule, preserving their existing native-type handling. An already RDF-typed native int/float whose lexical form is not digit-led (e.g. a negative number, `"-5"`) still passes through natively rather than falling back to text. Updated the module docstring's literal-attribute paragraph to describe this rule. Attribute *keys* remain sanitized CURIEs (unchanged) — the user's request for full-IRI keys was explicitly declined via AskUserQuestion due to a documented conflict with SHQL's `attributes: {key: value}` MongoDB dot-path filter.
- **tests/test_rdf_import.py** — Replaced `test_literal_conversion_unsafe_types_fall_back_to_lexical_string` with two tests reflecting the new split behavior: `test_literal_conversion_digit_led_decimal_becomes_native_float` (xsd:decimal "19.99" → native float 19.99, no longer text) and `test_literal_conversion_bare_date_still_falls_back_to_lexical_string` (xsd:date unchanged, still text). Added a new "Digit/quote lexical sniffing" test section: `test_user_example_quoted_string_becomes_text_bare_decimal_becomes_numeric` (reproduces the user's own ex:sex/ex:rating example), `test_digit_led_value_wins_even_when_rdf_typed_as_a_plain_string` (quoted `"12345"` → numeric 12345), `test_digit_led_value_that_fails_to_cast_falls_back_to_negative_one` (`"12.2abc"` → -1), `test_negative_typed_number_still_passes_through_natively` (`"-5"^^xsd:integer` → native -5, unaffected by the digit rule), `test_resource_valued_object_is_never_swept_into_an_attribute` (an IRI-valued object stays a hyperedge, never becomes an attribute, regardless of the new value-classification rule).
- **docs/help/notes/web-ui/export-import.md** — Updated the RDF mapping table's "literal-valued triple" row to describe the new digit-led-lexical-form → numeric / else → text classification (with the `-1` fallback and the boolean/date exemption), replacing the old "numbers, booleans and datetimes convert to native types" wording.
- **docs/api-reference.md** — Same update to the equivalent RDF mapping table row.
