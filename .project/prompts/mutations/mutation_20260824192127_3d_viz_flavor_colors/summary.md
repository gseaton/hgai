# Mutation Summary

## Intent
In the prior "diagram layout" mutation, all hyperedge→members ("flavor") links were deliberately given one fixed magenta color, moving flavor-specific color entirely onto text (the `flavor:<value>` label) in order to match the reference diagram, which uses a single edge-kind color rather than a color per flavor. The user has now asked for the opposite for this specific link: color the flavor link *by its flavor value* (giving `hub`, `symmetric`, `direct`, `transitive`, and `inverse-transitive` each a distinct, semantically-named color — "hub = gold, symmetric = green" as explicit examples), so the topology pattern a hyperedge implies is visible at a glance without reading the label text.

## Context
`hgai/models/hyperedge.py`'s `EdgeFlavor` enum defines exactly five values (`hub`, `symmetric`, `direct`, `transitive`, `inverse-transitive`), each describing a different relationship topology (star/hub, symmetric peers, directed chain, transitive chain, inverse-transitive chain). This is a bounded, small enum — a fixed color-per-value map is a natural, low-risk fit (no hashing needed, unlike the open-ended hypernode `type` field, which already uses a hash-based palette since arbitrary type strings can't be enumerated up front).

## What Changed and Why
- **Fixed 5-color flavor map** (`VIZ_FLAVOR_LINK_COLOR`) replaces the single `VIZ_LINK_HYPEREDGE_COLOR` constant used since the "diagram layout" mutation. Colors were chosen to be intuitively evocative where possible (gold for `hub` per the user's own example, green for `symmetric`) and mutually distinct from each other and from the unrelated relation-link colors already in use (amber for ordinary members, blue for the first member) so none of the color channels collide or get confused for one another.
- **`flavorSeen` tracking restored**: this had been intentionally dropped when the legend was simplified to a static two-row "edge kind" key in the diagram-layout mutation (since, at that point, color no longer varied by flavor, so a per-flavor legend had nothing to show). Now that color varies by flavor again, the per-flavor legend needed to come back — it now lists exactly the flavors present in the current render, each swatched with its actual color, so the mapping is discoverable rather than only inferable from the reference diagram or this session's chat history.
- **Relation-links (amber / first-member blue) were left untouched** — this request was specifically about the flavor-typed link (hyperedge→members), not the relation-typed links (members→member), which already carry their own distinct color scheme from the immediately preceding mutation.

## Key Decisions
- **A fixed map, not a hash-based palette**: unlike hypernode `type`, which is a free-text field with unbounded values (hence `vizColorForType`'s hash-into-a-12-color-palette approach), `flavor` is a closed 5-value enum defined in the backend model — a literal, curated map is more correct here (avoids incidental hash collisions and lets specific colors be chosen deliberately, as the user requested by example) and there was no reason to force it through the generic hashing helper.
- **Verification**: reused the CDP-over-headless-Chrome harness (still no Claude-in-Chrome extension in this environment). Since the seeded `hello-world` data only contained `hub`-flavored hyperedges, four additional test hyperedges (one each of `symmetric`, `direct`, `transitive`, `inverse-transitive`, all reusing existing `person:moe`/`person:larry` as members) were created via the REST API against the local test-only MongoDB instance to exercise every flavor. Confirmed all 5 flavor-links resolved to their intended distinct hex colors with no collisions, relation-link colors remained exactly `{amber, blue}` as before (unaffected), the legend listed all 5 flavors present, and a screenshot visually confirms distinctly colored flavor links (gold/green/violet/rose clearly visible; cyan present but harder to distinguish against the dark background in this particular camera angle). Zero console errors. Test infrastructure (local mongod — including the four disposable test hyperedges, which only exist in this session's throwaway scratchpad database — the hgai server process, and headless Chrome) was torn down afterward; no changes were made to the user's real data.
