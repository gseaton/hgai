# Mutation Summary

## Intent
The "SPARQL to SHQL Conversion Plan" produced earlier in this session existed only as a live Claude Docs artifact — useful for interactive review, but not version-controlled, not diffable, and not linkable from other repo docs the normal way. The user asked to bring it into the codebase as a real file, and in the same request asked for it to be extended: add `VALUES` and aggregate support to the transpiler plan, drawing on the prioritization already worked out in the immediately preceding `docs/architecture/sparql-vs-shql-gaps.md` (which had identified `VALUES` and `SUM`/`AVG`/`MIN`/`MAX` as the two Tier 1 "build now" gaps, both achievable without changing the shared SHQL engine).

## Context
`docs/architecture/` holds plain, frontmatter-free reference markdown (confirmed again here, following the same convention used for `sparql-vs-shql-gaps.md` earlier in this session). The plan's original content lived in a Claude Docs artifact bound to project id `7efd09e1-229b-485d-9c85-ac9be8ddca74`; retrieving it required the Claude Docs connector's `read` tool (`ref: {"object":"project","id":...}` for the tab/node ids, then a `view` read of the prose node) rather than the Artifact tool's own `read` action, which only returns the Claude Docs *viewer's* HTML shell for an artifact of this type, not the document's actual content — that distinction is called out explicitly in the artifact type's own instructions and confirmed by inspecting the `read` output before proceeding.

## What Changed and Why
The doc's content, read back as an XML-ish block-structured representation, was transcribed to clean markdown (pipe tables, `**bold**`/`*italic*`/`` `code` ``) rather than pasted as-is, since the Claude Docs internal representation isn't valid markdown on its own. While transcribing, the `VALUES` and aggregate-support additions were folded directly into the relevant existing sections rather than appended as a separate addendum, so the file reads as one coherent, current plan rather than a plan-plus-patch-notes: the lead's list of supported constructs, the §2 comparison table's `VALUES` and `GROUP BY`+aggregate rows, the §3 SHQL-cons paragraph, a new §5 Phase 2.5, an expanded Phase 4, a Phase 6 validation addition, and the §6 recommendation's scope statement were all updated together.

The aggregate-support design applied here is the specific one `sparql-vs-shql-gaps.md` had already worked out and justified: rather than extending `hgai_module_shql/engine.py`'s `aggregate:` block (a change to code every other SHQL consumer depends on), `SUM`/`AVG`/`MIN`/`MAX` are computed by the transpiler itself over a broad, unaggregated SHQL fetch. That document's caveat about this approach — SHQL's internal `search(..., limit=2000)` cap on a single pattern's candidate fetch means the transpiler-side computation is silently incomplete past that scale, not merely slow — was carried into the plan's Phase 4 description verbatim in substance, not softened, since omitting it here would let a reader of the plan alone miss a real correctness boundary that the companion gaps document had already surfaced.

`sparql-vs-shql-gaps.md` was updated afterward so its opening cross-reference points at the new local file instead of the now-secondary artifact link, and to note that its own Tier 1 recommendations have already been acted on — keeping the two documents from drifting out of sync with each other now that the plan has a permanent home in the repo.

## Key Decisions
- Retrieved the artifact's actual content via the Claude Docs connector's `read` tool rather than assuming the Artifact tool's `read` action would return it — the artifact type's own instructions state plainly that a "pages" (Claude Docs) artifact's page comes from the type, not the document, and the document must be read through the connector; verifying this before transcribing avoided writing the viewer's application shell to the repo by mistake.
- Folded the `VALUES`/aggregate additions into the plan's existing sections rather than adding a new "Recent Updates" section, since the plan is meant to read as the current state of the design, not a changelog — a future reader shouldn't have to reconcile an old §5 against a newer addendum to know what Phase 4 actually does today.
- Reused `sparql-vs-shql-gaps.md`'s already-established reasoning and specific wording (the 2,000-candidate cap, the client-side-computation strategy) rather than re-deriving it, since that document did the prioritization work this addition is directly implementing — restating it with different reasoning risked introducing an inconsistency between the two documents.
- Left the live Claude Docs artifact itself unmodified — the user asked for the content to be written to a file and the plan extended, not for the artifact to be kept in sync going forward. The repo file is now the authoritative, living version of the plan; the artifact remains as a point-in-time snapshot of the original review draft.
