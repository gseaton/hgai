# Exporting and importing hypergraphs

A hypergraph can be saved to a single file and imported into another HypergraphAI instance — to move data between servers, share a knowledge base, seed a new environment, or keep a portable copy of one graph. (For whole-database backups see [Backup and restore](help:help-backup).)

## The export file

Exports are named **`hgai-hypergraph-<graph-id>-<YYYYMMDDHHMMSS>.export.yml`** (UTC timestamp), for example `hgai-hypergraph-eden-20260920161601.export.yml`. It is a YAML document (JSON is also accepted on import):

```yaml
hgai_export: '1.0'          # format version
exported_at: '2026-09-20T16:16:01+00:00'
source: { server_id: hgai-local, server_name: HypergraphAI Local }
counts: { nodes: 9, edges: 8 }
graph:                       # the hypergraph's own definition
  id: eden
  label: Eden
  type: instantiated
  tags: []
nodes:                       # every hypernode (all statuses)
  - { id: "person:adam", label: Adam, type: Person, attributes: {} }
edges:                       # every hyperedge (all statuses)
  - { id: "edge:1", relation: "rel:parent", flavor: hub, members: [{ node_id: "person:adam", seq: 0 }] }
```

**What is included:** the hypergraph definition and *all* of its [hypernodes](help:help-hypernodes) and [hyperedges](help:help-hyperedges) — including `draft` and `archived` ones, validity dates, tags, attributes.

**What is not:** media *files* (only references to them exist on nodes and edges, and those references are dropped on import so nothing dangles), and other resources such as Notes or accounts. Timestamps, version numbers, the audit trail, edge hyperkeys and `created_by` are regenerated by the importing server.

## In the Web UI

Open **Hypergraphs**.

- **Export** — click the download button (⬇) on a hypergraph's row. Your browser saves the `.export.yml` file.
- **Import** — click **Import**, choose a file, then optionally:
  - a **Space** to own the new hypergraph ([Spaces](help:help-spaces)) — default none;
  - a **Hypergraph ID** to use instead of the one stored in the file;
  - the mode: **Create a new hypergraph** (fails if the ID is already taken) or **Merge into the hypergraph** (adds what is missing; creates the graph if absent).
  The result panel shows how many nodes and edges were imported, how many already existed, and any per-item errors.

## Merge never overwrites

In merge mode a node whose id already exists, and an edge whose id — or identity (same relation, members and validity window) — already exists, is **skipped**, not updated. To replace a graph, delete it first (or import under a new ID).

## In the shell

```
export -g eden                       # writes hgai-hypergraph-eden-<timestamp>.export.yml
export -g eden -o my-copy.yml
import -f hgai-hypergraph-eden-20260920161601.export.yml
import -f file.export.yml -g eden-v2      # under a different id
import -f file.export.yml --merge          # into an existing hypergraph
```

See [The hgsh shell](help:help-shell).

## Over REST

```bash
# export (YAML download; the suggested file name is in Content-Disposition)
curl -OJ "http://localhost:8357/api/v1/graphs/eden/export?format=yaml" -H "Authorization: Bearer $TOKEN"

# import into another server — the body is the raw file
curl -X POST "http://other-server:8357/api/v1/graphs/import?mode=create" \
  -H "Authorization: Bearer $OTHER_TOKEN" --data-binary @hgai-hypergraph-eden-20260920161601.export.yml
```

Add `graph_id=<id>` to rename, `mode=merge` to merge; space-scoped graphs use `/spaces/{space_id}/graphs/{id}/export` and `/spaces/{space_id}/graphs/import`. Details in [REST API](help:help-rest-api).

## The example hypergraphs are export files too

The seeds shipped in `scripts/seeds/` (`hello-world` and `eden`) are ordinary export files, loaded by `python scripts/seed_data.py`. Adding your own is as simple as dropping an `hgai-hypergraph-<id>.export.yml` file into that folder ([Quick Start](help:help-quick-start)).

## Good to know

- One bad item doesn't abort an import: it is counted as an error (the first 25 messages are shown) and everything else loads.
- Edge references to nodes that are not in the file (for example, cross-graph references) are kept as-is.
- Very large graphs export completely — there is no row cap — but the file is limited to 100 MB on import.
- Exporting needs *read* access to the graph; importing a new hypergraph needs only a signed-in account (like creating one), while merging into an existing one needs *write* access. Space imports need space membership.
